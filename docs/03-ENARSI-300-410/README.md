## ENARSI 和 ENCOR 的本质区别

| | **ENCOR** | **ENARSI** |
|:--|:--|:--|
| 核心问题 | **"怎么配？"** | **"配错了怎么查？"** |
| 知识广度 | 广（覆盖所有领域） | **窄而深**（路由 + VPN + 服务） |
| 题型 | 概念 + 配置 | **大量排障题**（给你一段配置和现象，让你找根因） |
| 难点 | 记忆量大 | **推理链条长**（协议之间的相互作用） |

**所以本篇的组织方式不同于 ENCOR**：每一章的重心是 **故障注入 → 症状 → 推导 → 根因**，而不是重复讲配置。

## 学习建议

**时间分配（8 周）**：

| 周 | 内容 |
|:--|:--|
| W1 | 01 EIGRP 深入 + Lab 05 |
| W2–W3 | **02 OSPF 深入**（重点：LSA 过滤和虚链路） |
| W4–W5 | **03 BGP 深入**（重点：选路操控和 RR） |
| W6 | **04 重分发**（★ 最重要，必须动手造环路） |
| W7 | 05 MPLS + 06 DMVPN + Lab 08/09 |
| W8 | 07 基础设施服务 + Lab 10 综合排障 + 总复习 |

**三条硬性要求**：

1. **每一章的"故障注入"环节必须自己做一遍。** ENARSI 的排障题是描述一个现象让你找原因——**只有亲手制造过那个现象，你才认得出来**。
2. **第 4 章的重分发环路必须自己造出来再修好。** 这是全书最重要的实验。
3. **养成"先看 LSDB/BGP表，再看路由表"的习惯。** 两者的差异告诉你问题在发送侧还是接收侧。

## 排障的通用思维框架

无论遇到什么故障，都可以套这个框架：

```
   ① 现象是什么？（精确描述，不要模糊）
      "A 能 ping B，B 不能 ping A" ≠ "网络不通"
        ↓
   ② 影响范围有多大？
      一台？一个网段？一个区域？全网？
      → 范围决定了问题在哪一层
        ↓
   ③ 什么时候开始的？改了什么？
      → 80% 的故障是变更引起的
        ↓
   ④ 分层定位：物理 → 链路 → 网络 → 传输 → 应用
      每一层用一个明确的命令验证
        ↓
   ⑤ 二分法缩小范围
      中间点测试，判断问题在前半段还是后半段
        ↓
   ⑥ 对比法
      能通的 vs 不能通的，配置差在哪？
        ↓
   ⑦ 验证假设（★ 关键）
      不要凭猜测就改配置，先用命令证明你的假设
```

详见 [Stage 5 · 排障方法论](../05-排障方法论/README.md)。

## 过关自检

学完本篇，闭卷回答，答对 8 题以上再约考：

1. EIGRP 出现 SIA 的根本原因是什么？两个最有效的预防手段？
2. OSPF 邻居卡在 EXSTART，除了 MTU 还可能是什么原因？
3. OSPF 的 `area X filter-list` 和 `distribute-list` 分别过滤什么？
4. 虚链路的穿越区域为什么不能是 Stub？
5. iBGP 学到的路由为什么可能显示 `inaccessible`？
6. BGP 的 `r`（RIB-failure）标记意味着什么？
7. **双点双向重分发为什么会产生环路？三种解决方法是什么？**
8. MPLS 标签的压入、交换、弹出分别发生在哪里？什么是 PHP？
9. DMVPN Phase 1/2/3 的核心区别是什么？NHRP 起什么作用？
10. `ip helper-address` 除了 DHCP 还转发哪些广播？怎么精简？
11. uRPF 的严格模式和松散模式有什么区别？什么场景下严格模式会误伤？

答案分散在各章。
