# 04 · 路由重分发与路由策略

> ⚠️ **全书最容易出真实事故的一章。**
> 通过标准：**能自己造出一个重分发环路，并用三种方法分别修好它。**

## ① 这章解决什么问题

企业并购、历史遗留、多厂商共存——现实中的网络往往同时跑着多个路由协议：

```
   总部（OSPF）  ←→  分支（EIGRP，历史遗留的纯 Cisco 环境）
   核心（OSPF）  ←→  运营商（BGP）
   数据中心（BGP + EVPN）  ←→  园区（OSPF）
```

**它们之间需要交换路由，这就是重分发（Redistribution）。**

但重分发是**路由环路和黑洞的高发区**。原因很简单：

> **路由协议之间没有"共同语言"。**
>
> OSPF 的 cost 和 EIGRP 的复合度量值**没有可比性**；重分发时 metric 必须重新赋值，而**这个新值丢失了原始的路径信息**。加上不同协议的 AD 差异，很容易出现"A 协议学到的路由被重分发进 B，B 又重分发回 A，而 A 认为 B 的路由更优"——**环路就这样形成了。**

## ② 重分发基础

### 2.1 基本配置

```cisco
! ── OSPF → EIGRP ──
R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1 metric 100000 100 255 1 1500
!                                     ↑      ↑   ↑   ↑  ↑
!                              带宽(Kbps) 延迟 可靠性 负载 MTU

! ── EIGRP → OSPF ──
R1(config)# router ospf 1
R1(config-router)# redistribute eigrp 100 subnets
!                                          ↑ ★ 必须加，否则只重分发主类网络

! ── 静态 → OSPF ──
R1(config-router)# redistribute static subnets metric 20 metric-type 1

! ── 直连 → OSPF ──
R1(config-router)# redistribute connected subnets

! ── BGP → OSPF ──
R1(config-router)# redistribute bgp 65001 subnets

! ── OSPF → BGP ──
R1(config)# router bgp 65001
R1(config-router)# redistribute ospf 1 match internal external 1 external 2
```

### 2.2 各协议的默认 Metric（★ 必背）

| 目标协议 | 默认 metric | 不指定会怎样 |
|:--|:--|:--|
| **OSPF** | **20**（BGP 来源是 1） | ✅ 正常工作 |
| **BGP** | 从 IGP 继承 | ✅ 正常 |
| **RIP** | **无穷大** | ❌ **路由不可用** |
| **EIGRP** | **无穷大** | ❌ **路由不可用** |
| IS-IS | 0 | ✅ 正常 |

> ⚠️ **重分发进 EIGRP 和 RIP 时，必须显式指定 metric**，否则默认是无穷大（不可达），**路由会被通告但对方认为不可用**。
>
> 这是"配了重分发但路由学不到"的经典原因。

**三种指定 metric 的方式**：
```cisco
! 方式 1：在 redistribute 语句里指定
R1(config-router)# redistribute ospf 1 metric 100000 100 255 1 1500

! 方式 2：设置协议的默认 metric（★ 推荐，更简洁）
R1(config)# router eigrp 100
R1(config-router)# default-metric 100000 100 255 1 1500
R1(config-router)# redistribute ospf 1

! 方式 3：用 route-map（最灵活）
R1(config)# route-map OSPF-TO-EIGRP permit 10
R1(config-route-map)#  set metric 100000 100 255 1 1500
R1(config-router)# redistribute ospf 1 route-map OSPF-TO-EIGRP
```

### 2.3 `subnets` 关键字（OSPF 特有）

```cisco
! ❌ 不加 subnets
R1(config-router)# redistribute static
! 只重分发【主类网络】（如 10.0.0.0/8、192.168.1.0/24）
! ★ 所有非主类的子网（10.1.1.0/24、192.168.1.128/25）都不会被重分发 ★

! ✅ 加 subnets
R1(config-router)# redistribute static subnets
```

> **这是 OSPF 重分发最常见的遗漏。** 症状：重分发了但对方只学到很少几条路由（或一条都没有）。
>
> **口诀：重分发进 OSPF，永远加 `subnets`。**
>
> IOS-XE 较新版本可能默认启用，但**显式写上是好习惯**。

### 2.4 重分发后的 AD 与 Metric 类型

| 协议 | 重分发进来的路由 | AD | 标记 |
|:--|:--|:--|:--|
| **OSPF** | 外部路由 | **110** | **`O E1` / `O E2`**（默认 E2） |
| **EIGRP** | 外部路由 | **170**（内部是 90） | **`D EX`** |
| **BGP** | — | 20/200 | ORIGIN 变成 `?`（incomplete） |
| RIP | 外部 | 120 | — |

**★ EIGRP 外部路由 AD = 170**，比内部的 90 差很多。这在双点重分发场景下是环路的关键因素之一（见第 ③ 节）。

## ③ 路由环路：为什么会发生（★ 全章核心）

### 3.1 单点重分发：安全

```
   OSPF 域 ──── [R1] ──── EIGRP 域
                 ↑
            唯一的重分发点
```

**只有一个出入口，路由不可能绕回来 → 不会有环路。**

### 3.2 双点单向重分发：安全

```
   OSPF ──[R1]──> EIGRP
   OSPF ──[R2]──> EIGRP
   
   两个点，但都是【单向】的（只从 OSPF 到 EIGRP）
   → 路由不会回流 → 安全
```

### 3.3 双点双向重分发：★ 环路高发 ★

```
   ┌──────────────────────────────────┐
   │                                  │
   │   OSPF 域          EIGRP 域       │
   │                                  │
   │      ┌─────[R1]─────┐            │
   │      │  双向重分发   │            │
   │  [R3]│              │[R4]        │
   │      │              │            │
   │      └─────[R2]─────┘            │
   │         双向重分发                │
   └──────────────────────────────────┘
```

**这是现实中最常见的部署（为了冗余，必然有两个重分发点）。**

### 3.4 环路的形成过程（★ 必须理解）

**假设 `10.1.1.0/24` 原本是 OSPF 域内的路由（R3 通告的）：**

```
   ① R3 在 OSPF 里通告 10.1.1.0/24
      → R1 和 R2 都通过 OSPF 学到（AD 110，内部路由 O）
   
   ② R1 把它重分发进 EIGRP
      → EIGRP 域里出现 10.1.1.0/24（外部路由 D EX，AD 170）
   
   ③ R2 通过 EIGRP 也学到了这条路由（D EX，AD 170）
      → ★ 但 R2 同时还有 OSPF 学到的（O，AD 110）★
      → AD 110 < 170，所以 R2 还是用 OSPF 的 ✓ 暂时正常
   
   ④ ★ 关键时刻：R2 把 EIGRP 域的路由重分发回 OSPF ★
      → R2 会把它从 EIGRP 学到的 10.1.1.0/24 重分发进 OSPF
      → 变成 OSPF 外部路由 O E2
   
   ⑤ R1 通过 OSPF 收到这条 O E2 路由（AD 110）
      → ★ R1 现在有两条 10.1.1.0/24：★
         · OSPF 内部 O    （从 R3 学到，AD 110）
         · OSPF 外部 O E2 （从 R2 学到，AD 110）
      → AD 相同，但 OSPF 内部路由优于外部（选路顺序：Intra > Inter > E1 > E2）
      → R1 依然选内部 ✓ 暂时正常
   
   ⑥ ★★ 真正的危险时刻：R3 到 10.1.1.0/24 的链路断了 ★★
      → OSPF 域里的原始路由消失
      → R1 失去 OSPF 内部路由
      → ★ 但 R1 还有从 R2 那里通过 OSPF 学到的 O E2 路由！★
      → R1 认为"去 10.1.1.0/24 走 R2"
      
      → 而 R2 的这条路由是从 EIGRP 学来的
      → EIGRP 里这条路由是 R1 重分发进去的
      → R1 说走 R2，R2 说走 R1
      
      ★★★ 路由环路形成 ★★★
      流量在 R1 和 R2 之间来回弹，直到 TTL 耗尽
```

**如果 AD 关系更"糟糕"，环路会立即形成，甚至不需要链路故障。**

**核心问题总结**：
> **重分发丢失了"这条路由原本是哪个协议的"这个信息。**
>
> R1 无法区分"这是 OSPF 域原生的路由"和"这是我自己重分发进 EIGRP 又被 R2 送回来的路由"。

## ④ 三种解决方法（★ 必须掌握）

### 方法 1：Route Tag（★ 最优雅，首选）

**思路**：重分发时给路由**打标记**，重分发回来时**根据标记拒绝**。

```cisco
! ══════ R1 配置 ══════

! ── 出方向：OSPF → EIGRP，打标记 100 ──
R1(config)# route-map OSPF-TO-EIGRP permit 10
R1(config-route-map)#  set tag 100                        ! ★ 打标记
R1(config-route-map)#  set metric 100000 100 255 1 1500

R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1 route-map OSPF-TO-EIGRP

! ── 入方向：EIGRP → OSPF，拒绝带标记 100 的 ──
R1(config)# route-map EIGRP-TO-OSPF deny 10
R1(config-route-map)#  match tag 100                      ! ★ 认出是自己打的标记
R1(config)# route-map EIGRP-TO-OSPF permit 20
R1(config-route-map)#  set tag 200                        ! 给 EIGRP→OSPF 的打另一个标记

R1(config)# router ospf 1
R1(config-router)# redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF

! ── 反方向也要对称配置 ──
R1(config)# route-map OSPF-TO-EIGRP deny 5
R1(config-route-map)#  match tag 200                      ! ★ 拒绝带标记 200 的
! （注意 seq 5 要排在 seq 10 前面）

! ══════ R2 完全相同的配置 ══════
```

**完整的对称配置（推荐直接抄）**：

```cisco
! ═══ 两台重分发点（R1 和 R2）都配置完全相同的内容 ═══

! OSPF → EIGRP
route-map OSPF-TO-EIGRP deny 5
 match tag 200                          ! 拒绝来自 EIGRP 的（防回流）
route-map OSPF-TO-EIGRP permit 10
 set tag 100                            ! 标记为"来自 OSPF"
 set metric 100000 100 255 1 1500

! EIGRP → OSPF
route-map EIGRP-TO-OSPF deny 5
 match tag 100                          ! 拒绝来自 OSPF 的（防回流）
route-map EIGRP-TO-OSPF permit 10
 set tag 200                            ! 标记为"来自 EIGRP"

router eigrp 100
 redistribute ospf 1 route-map OSPF-TO-EIGRP

router ospf 1
 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF
```

**验证**：
```cisco
R2# show ip route ospf | include 10.1.1.0
O    10.1.1.0/24 [110/100] via ... 
! 只有内部路由，没有 O E2 → 没有回流 ✓

R2# show ip ospf database external
! 不应该看到 R1 重分发进 EIGRP 又回流的那些路由

R1# show ip eigrp topology 10.1.1.0/24
! 看 tag
R1# show ip route 10.1.1.0 | include tag
      Route tag 100
```

> **★ Route Tag 是最优雅的方案**：
> - 不依赖 AD 调整（AD 调整是"局部"的，容易顾此失彼）
> - 逻辑清晰，一看就懂
> - 自动适应拓扑变化
> - **两台重分发点配置完全相同**，易维护
>
> **这是 ENARSI 考试和实际工作的首选答案。**

### 方法 2：调整 AD

**思路**：让"重分发回来的路由"的 AD 比"原生路由"更差。

```cisco
! 让 OSPF 的外部路由 AD 变得比 EIGRP 外部路由（170）还差
R1(config)# access-list 10 permit 10.1.1.0 0.0.0.255
R1(config)# router ospf 1
R1(config-router)# distance ospf external 180
! 或针对特定前缀
R1(config-router)# distance 180 0.0.0.0 255.255.255.255 10
```

```cisco
! 或者调整 EIGRP 的外部 AD
R1(config)# router eigrp 100
R1(config-router)# distance eigrp 90 200
!                                 ↑   ↑
!                              内部  外部（从 170 调到 200）
```

**⚠️ 缺点**：
1. **是"局部行为"** —— 只影响配了这条命令的那台路由器。要在所有重分发点上一致配置，容易遗漏。
2. **难以覆盖所有情况** —— 拓扑变化后 AD 关系可能不再成立。
3. **容易顾此失彼** —— 调了 AD 解决了这个环路，可能引入新的次优路由。

**只在无法用 Tag 时（比如设备不支持）才考虑。**

### 方法 3：路由过滤（distribute-list / prefix-list）

**思路**：明确指定"哪些前缀允许重分发"。

```cisco
R1(config)# ip prefix-list OSPF-NETS seq 5 permit 10.1.0.0/16 le 32
R1(config)# ip prefix-list OSPF-NETS seq 10 deny 0.0.0.0/0 le 32

R1(config)# route-map FILTER-REDIST permit 10
R1(config-route-map)#  match ip address prefix-list OSPF-NETS

R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1 route-map FILTER-REDIST metric 100000 100 255 1 1500
```

**⚠️ 缺点**：
1. **需要维护前缀列表** —— 网络增加新网段就要改
2. **容易遗漏** —— 忘了加新网段导致路由不通
3. **不适应动态变化**

**适合场景**：网段规划非常稳定，且只需要重分发少量固定的前缀。

### 三种方法对比

| 方法 | 优雅度 | 维护成本 | 适应性 | 推荐度 |
|:--|:--|:--|:--|:--|
| **Route Tag** | ★★★★★ | 低 | ★ 自动适应 | ★★★★★ **首选** |
| **调整 AD** | ★★ | 中 | 差 | ★★ 备选 |
| **路由过滤** | ★★★ | **高** | 差 | ★★★ 特定场景 |

**实践建议：Route Tag 为主，必要时配合过滤做二次保险。**

## ⑤ Route-Map 完全指南

Route-map 是 IOS 里最强大的策略工具，重分发、BGP 策略、PBR、NAT 都用它。

### 5.1 结构

```cisco
route-map NAME {permit|deny} SEQ
  match <条件1>
  match <条件2>          ← 多个 match 是【AND】关系
  set <动作1>
  set <动作2>
```

**执行逻辑**：
```
   自上而下按 seq 顺序
        ↓
   某条 seq 的【所有 match 都满足】？
        ├─ 是 → 执行该 seq 的动作
        │        ├─ permit → 执行 set，然后【停止】
        │        └─ deny   → 拒绝，然后【停止】
        └─ 否 → 继续下一条 seq
        ↓
   全部不匹配 → ★ 隐含 deny ★
```

**三个关键规则**：
1. **同一 seq 内的多个 `match` 是 AND 关系**（都要满足）
2. **同一 `match` 语句里的多个值是 OR 关系**（`match tag 100 200` = tag 是 100 或 200）
3. **末尾有隐含的 `deny`**（★ 必须加兜底）

### 5.2 常用 match

```cisco
! ── 匹配前缀 ──
route-map RM permit 10
 match ip address 10                              ! 用 ACL
 match ip address prefix-list MY-PREFIXES         ! ★ 用 prefix-list（推荐）

! ── 匹配下一跳 ──
 match ip next-hop 20
 match ip next-hop prefix-list NH-LIST

! ── 匹配路由来源 ──
 match ip route-source 30

! ── 匹配 metric ──
 match metric 100
 match metric 100 +-10                            ! 90-110 范围

! ── 匹配 tag ──
 match tag 100 200 300                            ! OR 关系

! ── 匹配接口 ──
 match interface GigabitEthernet0/1

! ── 匹配路由类型 ──
 match route-type internal
 match route-type external type-1
 match route-type external type-2
 match route-type level-1                         ! IS-IS

! ── BGP 专用 ──
 match as-path 1
 match community CUSTOMER
 match extcommunity RT-LIST
 match local-preference 200
```

### 5.3 常用 set

```cisco
route-map RM permit 10
 ! ── 通用 ──
 set metric 100
 set metric-type type-1                           ! OSPF E1/E2
 set tag 100
 set level level-1                                ! IS-IS

 ! ── EIGRP metric（五元组）──
 set metric 100000 100 255 1 1500

 ! ── BGP 专用 ──
 set local-preference 200
 set weight 500
 set as-path prepend 65001 65001 65001
 set community 65001:100 additive
 set community no-export
 set origin igp
 set ip next-hop 10.0.0.1
 set ip next-hop peer-address
 set ip next-hop self

 ! ── PBR 专用 ──
 set ip next-hop 10.0.0.1
 set ip next-hop verify-availability 10.0.0.1 1 track 1
 set interface GigabitEthernet0/1
 set ip default next-hop 10.0.0.1
 set ip precedence critical
 set ip dscp ef
```

### 5.4 `continue` 关键字（进阶）

**默认行为**：匹配到一条 permit 的 seq 就停止。

**`continue` 让它继续往下匹配**：
```cisco
route-map COMPLEX permit 10
 match ip address prefix-list A
 set local-preference 200
 continue 30                                      ! ★ 跳到 seq 30 继续

route-map COMPLEX permit 20
 match ip address prefix-list B
 set weight 100

route-map COMPLEX permit 30
 set community 65001:100 additive
```

**用途**：给同一条路由**叠加多个属性**，而不需要写大量重复的组合条件。

## ⑥ 策略路由（PBR）

**普通路由**：只看目的 IP。
**PBR**：可以根据**源 IP、协议、端口、包大小、DSCP** 等条件决定路径。

### 6.1 配置

```cisco
! ── 定义流量 ──
R1(config)# ip access-list extended FROM-SALES
R1(config-ext-nacl)#  permit ip 192.168.20.0 0.0.0.255 any

R1(config)# ip access-list extended P2P-TRAFFIC
R1(config-ext-nacl)#  permit tcp any any range 6881 6890

! ── 定义策略 ──
R1(config)# route-map PBR-POLICY permit 10
R1(config-route-map)#  match ip address FROM-SALES
R1(config-route-map)#  set ip next-hop 10.0.11.1                 ! 走电信

R1(config)# route-map PBR-POLICY permit 20
R1(config-route-map)#  match ip address P2P-TRAFFIC
R1(config-route-map)#  set ip next-hop 10.0.22.1                 ! P2P 走联通

R1(config)# route-map PBR-POLICY permit 30
! ★ 空的 permit = 其余流量走正常路由表 ★

! ── 应用（★ 在【入接口】上）──
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip policy route-map PBR-POLICY

! ── 对路由器【自己产生】的流量应用 ──
R1(config)# ip local policy route-map PBR-POLICY

! ── 查看 ──
R1# show ip policy
R1# show route-map PBR-POLICY
R1# debug ip policy
```

### 6.2 `set` 动作的优先级

| 动作 | 行为 |
|:--|:--|
| **`set ip next-hop`** | **强制走这个下一跳**（即使路由表里有更好的） |
| **`set ip default next-hop`** | **路由表里没有匹配时**才走这个下一跳 |
| `set interface` | 强制从这个接口发出 |
| `set ip default interface` | 路由表没匹配时才走这个接口 |

> **`next-hop` vs `default next-hop` 的区别很重要**：
> - `set ip next-hop` = **PBR 优先于路由表**
> - `set ip default next-hop` = **路由表优先于 PBR**
>
> 后者更"温和"，适合"正常走路由表，路由表没有时才用备用出口"的场景。

### 6.3 PBR + IP SLA（避免黑洞）

**问题**：`set ip next-hop` 强制走某个下一跳，**即使那个下一跳已经不可达**——流量进黑洞。

```cisco
! ── 定义探测 ──
R1(config)# ip sla 1
R1(config-ip-sla)#  icmp-echo 10.0.11.1
R1(config-ip-sla-echo)#   frequency 5
R1(config)# ip sla schedule 1 life forever start-time now
R1(config)# track 1 ip sla 1 reachability
R1(config-track)#  delay down 10 up 30

! ── PBR 挂钩 track ──
R1(config)# route-map PBR-POLICY permit 10
R1(config-route-map)#  match ip address FROM-SALES
R1(config-route-map)#  set ip next-hop verify-availability 10.0.11.1 1 track 1
!                                                                   ↑      ↑
!                                                                 序号   track对象
R1(config-route-map)#  set ip next-hop verify-availability 10.0.22.1 2 track 2
!                                                                   ↑ 备用
```

**行为**：track 1 down 时，自动使用序号 2 的下一跳。

> **★ 生产环境的 PBR 必须配 `verify-availability` + track**，否则下一跳失效时流量全部进黑洞，而且**普通的路由收敛救不了它**（因为 PBR 优先于路由表）。

## ⑨ 自测题

**1.** 双点双向重分发为什么会产生路由环路？

<details><summary>答案</summary>

**根本原因：重分发丢失了"这条路由原本属于哪个协议"这个信息。**

```
   OSPF 域 ──[R1]── EIGRP 域
        │             │
        └──[R2]───────┘
        （两个点，都是双向重分发）
```

**环路形成过程**：

```
   ① R3 在 OSPF 里通告 10.1.1.0/24
      → R1、R2 都通过 OSPF 学到（内部路由 O，AD 110）

   ② R1 把它重分发进 EIGRP
      → EIGRP 域出现这条路由（外部 D EX，AD 170）

   ③ R2 从 EIGRP 学到它（D EX，AD 170）
      → 但 R2 还有 OSPF 学到的（O，AD 110）→ 用 OSPF ✓

   ④ ★ R2 把从 EIGRP 学到的这条路由重分发【回】OSPF ★
      → 变成 OSPF 外部路由 O E2

   ⑤ R1 通过 OSPF 收到 R2 通告的 O E2
      → R1 有两条：O（内部）和 O E2（外部）
      → OSPF 选路：内部 > 外部 → 用内部 ✓ 暂时正常

   ⑥ ★★ 危险时刻：R3 的源链路断了 ★★
      → OSPF 域里的原始路由消失
      → R1 只剩下从 R2 学到的 O E2
      → R1："去 10.1.1.0/24 走 R2"
      → 而 R2 的这条路由来自 EIGRP，EIGRP 里的这条是 R1 放进去的
      → R2："去 10.1.1.0/24 走 R1"
      
      ★★★ 环路 ★★★
```

**核心问题**：
```
   R1 无法区分：
   · "这是 OSPF 域原生的路由"
   · "这是我自己重分发进 EIGRP，又被 R2 送回 OSPF 的路由"
   
   ★ 重分发把路由的"血统"洗掉了 ★
```

**为什么单点重分发不会有这个问题**：
```
   只有一个出入口 → 路由不可能从另一个点绕回来
```

**为什么双点单向也安全**：
```
   OSPF ──[R1]──> EIGRP
   OSPF ──[R2]──> EIGRP
   （都是单向，没有回流路径）
```

**但现实中必须双点双向**（为了冗余），所以**必须做防环**。

**三种解决方法**：

| 方法 | 原理 | 推荐度 |
|:--|:--|:--|
| **① Route Tag** | 重分发时打标记，回流时按标记拒绝 | ★★★★★ |
| **② 调整 AD** | 让回流的路由 AD 更差 | ★★ |
| **③ 路由过滤** | 明确指定允许重分发的前缀 | ★★★ |

**Route Tag 的标准配置（R1 和 R2 完全相同）**：
```cisco
route-map OSPF-TO-EIGRP deny 5
 match tag 200                    ! 拒绝来自 EIGRP 的
route-map OSPF-TO-EIGRP permit 10
 set tag 100                      ! 标记为"来自 OSPF"
 set metric 100000 100 255 1 1500

route-map EIGRP-TO-OSPF deny 5
 match tag 100                    ! 拒绝来自 OSPF 的
route-map EIGRP-TO-OSPF permit 10
 set tag 200                      ! 标记为"来自 EIGRP"

router eigrp 100
 redistribute ospf 1 route-map OSPF-TO-EIGRP
router ospf 1
 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF
```

**验证修复成功的标志**：断掉源之后，路由**消失（不可达）**，而不是"通过环路假装可达"。
</details>

**2.** 重分发进 OSPF 时为什么要加 `subnets`？

<details><summary>答案</summary>

**不加 `subnets`，OSPF 只重分发【主类网络（classful）】的路由，所有子网都会被忽略。**

```cisco
! ❌ 不加
R1(config-router)# redistribute static
! 只重分发：10.0.0.0/8、172.16.0.0/16、192.168.1.0/24 这类主类网络

! ✅ 加了
R1(config-router)# redistribute static subnets
! 重分发所有路由，包括 10.1.1.0/24、192.168.1.128/25 等子网
```

**主类网络的定义**（历史遗留的有类概念）：

| 类 | 范围 | 默认掩码 |
|:--|:--|:--|
| A | 1.0.0.0 – 126.255.255.255 | /8 |
| B | 128.0.0.0 – 191.255.255.255 | /16 |
| C | 192.0.0.0 – 223.255.255.255 | /24 |

**举例**：
```
   要重分发的静态路由：
   · 10.0.0.0/8       ← 主类（A 类默认 /8）✅ 会被重分发
   · 10.1.1.0/24      ← 子网 ❌ 不会
   · 172.16.0.0/16    ← 主类（B 类默认 /16）✅ 会
   · 172.16.1.0/24    ← 子网 ❌ 不会
   · 192.168.1.0/24   ← 主类（C 类默认 /24）✅ 会
   · 192.168.1.128/25 ← 子网 ❌ 不会
```

**在现代网络里，绝大多数路由都是子网**（VLSM 早已普及），所以**不加 `subnets` 基本等于什么都没重分发**。

**症状**：
```cisco
! 配了重分发
R1(config-router)# redistribute static

! 但对方一条路由都没学到（或只学到很少几条）
R2# show ip route ospf
! 空，或者只有零星几条主类网络
```

**排查**：
```cisco
R1# show ip protocols | section ospf
Routing Protocol is "ospf 1"
  ...
  Redistributing External Routes from,
    static
    ↑ 注意这里没有 "with subnets" 或类似提示

R1# show run | include redistribute
 redistribute static                    ← ★ 缺 subnets

R1# show ip ospf database external
! 数量远少于预期
```

**修复**：
```cisco
R1(config-router)# redistribute static subnets
```

**记忆口诀**：
> **重分发进 OSPF，永远加 `subnets`。**

**注意**：
- **只有 OSPF 有这个关键字**。EIGRP、BGP、IS-IS 都没有这个限制。
- **较新的 IOS-XE 版本可能默认启用**，但**显式写上是好习惯**（跨版本兼容、意图明确）。

**完整的 OSPF 重分发模板**：
```cisco
R1(config)# router ospf 1
R1(config-router)# redistribute static subnets metric 20 metric-type 1 route-map STATIC-TO-OSPF
R1(config-router)# redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF
R1(config-router)# redistribute connected subnets route-map CONN-TO-OSPF
!                                        ↑↑↑↑↑↑↑ 永远不要忘
```
</details>

**3.** 重分发进 EIGRP 时不指定 metric 会怎样？

<details><summary>答案</summary>

**路由会被通告出去，但 metric 是【无穷大】，对方认为它不可达，不会装入路由表。**

**症状很迷惑**：
- 重分发配置看起来正确
- `show ip eigrp topology` 里能看到路由
- **但路由表里没有**

```cisco
! ❌ 没指定 metric
R1(config)# router eigrp 100
R1(config-router)# redistribute ospf 1

! 在对端 R4 上：
R4# show ip eigrp topology
P 10.1.1.0/24, 0 successors, FD is Inaccessible
                              ↑↑↑↑↑↑↑↑↑↑↑↑ 无穷大

R4# show ip route eigrp | include 10.1.1.0
! 空 —— 路由不在表里
```

**各协议的默认 metric 对照**：

| 目标协议 | 默认 metric | 后果 |
|:--|:--|:--|
| **OSPF** | **20**（从 BGP 来是 1） | ✅ 正常 |
| **BGP** | 从 IGP 继承 | ✅ 正常 |
| **IS-IS** | 0 | ✅ 正常 |
| **EIGRP** | **无穷大** | ❌ **不可达** |
| **RIP** | **无穷大** | ❌ **不可达** |

**为什么 EIGRP 和 RIP 是无穷大**：

因为它们的 metric 无法从其他协议"自然推导"：
- OSPF 的 cost 是一个数字，EIGRP 需要**五个参数**（带宽、延迟、可靠性、负载、MTU）
- 协议设计者认为"没有合理的默认值"，宁可让管理员显式指定，也不要猜一个可能错误的值

**三种指定 metric 的方法**：

```cisco
! ── 方法 1：在 redistribute 语句里指定 ──
R1(config-router)# redistribute ospf 1 metric 100000 100 255 1 1500
!                                             ↑      ↑   ↑  ↑  ↑
!                                        带宽Kbps 延迟 可靠性 负载 MTU

! ── 方法 2：设置协议默认 metric（★ 推荐，最简洁）──
R1(config)# router eigrp 100
R1(config-router)# default-metric 100000 100 255 1 1500
R1(config-router)# redistribute ospf 1
R1(config-router)# redistribute static
R1(config-router)# redistribute connected
! ★ 一次设置，所有重分发都用这个值

! ── 方法 3：用 route-map（最灵活，可按前缀区分）──
R1(config)# route-map OSPF-TO-EIGRP permit 10
R1(config-route-map)#  match ip address prefix-list IMPORTANT
R1(config-route-map)#  set metric 1000000 10 255 1 1500      ! 重要路由给好 metric
R1(config)# route-map OSPF-TO-EIGRP permit 20
R1(config-route-map)#  set metric 100000 1000 255 1 1500     ! 其他给差 metric
R1(config-router)# redistribute ospf 1 route-map OSPF-TO-EIGRP
```

**metric 五参数的含义**：

| 参数 | 单位 | 建议值 | 说明 |
|:--|:--|:--|:--|
| **带宽** | Kbps | 100000（100Mbps） | 影响 metric 计算 |
| **延迟** | 十微秒 | 100（=1000微秒） | 影响 metric 计算 |
| 可靠性 | 0-255 | 255（最可靠） | 默认 K 值下不参与计算 |
| 负载 | 1-255 | 1（最轻） | 默认 K 值下不参与计算 |
| **MTU** | 字节 | 1500 | 不参与计算，但必须填 |

**默认 K 值（K1=1, K2=0, K3=1, K4=0, K5=0）下**，只有**带宽和延迟**参与计算。

**验证**：
```cisco
R1# show ip protocols | section eigrp
Routing Protocol is "eigrp 100"
  Redistributing: ospf 1, static, connected
  ★ Default redistribution metric is 100000 100 255 1 1500 ★

R4# show ip eigrp topology 10.1.1.0/24
P 10.1.1.0/24, 1 successors, FD is 2560002816
                              ↑ 有具体数值了 ✓

R4# show ip route eigrp | include 10.1.1.0
D EX 10.1.1.0/24 [170/2560002816] via 10.0.14.1, ...
     ↑ EX = 外部路由，AD 170
```

**RIP 同理**：
```cisco
R1(config)# router rip
R1(config-router)# default-metric 5                  ! 跳数
R1(config-router)# redistribute ospf 1
```
</details>

**4.** Route Tag 防环的原理是什么？为什么比调 AD 更好？

<details><summary>答案</summary>

**原理：重分发时给路由打上"来源标记"，重分发回来时根据标记识别并拒绝。**

```
   ① OSPF → EIGRP 时：★ 打标记 100 ★（意思是"这条路由来自 OSPF"）
   
   ② EIGRP → OSPF 时：★ 检查标记，是 100 的拒绝 ★
      （"这条路由本来就是从 OSPF 来的，不能再送回去"）
   
   ③ 反方向同理：EIGRP → OSPF 打标记 200，OSPF → EIGRP 拒绝标记 200
```

**标准配置（两台重分发点完全相同）**：
```cisco
! ── OSPF → EIGRP ──
route-map OSPF-TO-EIGRP deny 5
 match tag 200                          ! 拒绝"来自 EIGRP"的路由
route-map OSPF-TO-EIGRP permit 10
 set tag 100                            ! 标记为"来自 OSPF"
 set metric 100000 100 255 1 1500

! ── EIGRP → OSPF ──
route-map EIGRP-TO-OSPF deny 5
 match tag 100                          ! 拒绝"来自 OSPF"的路由
route-map EIGRP-TO-OSPF permit 10
 set tag 200                            ! 标记为"来自 EIGRP"

router eigrp 100
 redistribute ospf 1 route-map OSPF-TO-EIGRP
router ospf 1
 redistribute eigrp 100 subnets route-map EIGRP-TO-OSPF
```

**为什么比调 AD 更好**：

| 维度 | **Route Tag** | **调整 AD** |
|:--|:--|:--|
| **作用范围** | 路由属性，**随路由传播** | ★ **只影响配置它的那台设备**（局部行为） |
| **适应拓扑变化** | ✅ **自动适应** | ❌ 拓扑变了 AD 关系可能失效 |
| **配置一致性** | 两个重分发点配**完全相同**的内容 | 需要精心计算每台的 AD |
| **可读性** | 意图明确（"这是从 OSPF 来的"） | 一堆数字，难懂 |
| **副作用** | 几乎没有 | ★ **可能引入次优路由** |
| **维护性** | 加新协议只需加新 tag | 要重新计算所有 AD 关系 |

**调 AD 的三个具体问题**：

**① AD 是局部的**
```cisco
R1(config-router)# distance ospf external 180
```
这条命令**只影响 R1 自己的路由表**。R2 完全不知道。如果 R2 上没有对称配置，环路依然存在。

**② 拓扑变化后可能失效**
```
   你精心计算了 AD：
   OSPF 外部 180 > EIGRP 外部 170  → EIGRP 赢，不会环路 ✓
   
   但如果网络加了第三个协议（比如引入了 BGP）
   或者某条路径的协议来源变了
        ↓
   ★ 原来的 AD 关系可能不再成立 ★
```

**③ 引入次优路由**
```
   为了防环把 OSPF 外部 AD 调到 180
        ↓
   但某些场景下 OSPF 外部路由确实是更优的路径
        ↓
   ★ 流量被迫走了更差的路径 ★
```

**Route Tag 没有这些问题**：
- Tag 是路由的一个属性，**随路由一起传播**
- 无论拓扑怎么变，"这条路由来自哪个协议"这个事实不变
- 不影响任何路径选择，只影响"要不要重分发"

**更进一步：Tag 可以做更精细的策略**

```cisco
! 用不同的 tag 区分不同的来源
route-map REDIST-TO-OSPF permit 10
 match tag 100                          ! 来自 OSPF（拒绝）
 ! deny

route-map REDIST-TO-OSPF permit 20
 match tag 300                          ! 来自静态路由
 set metric-type type-1                 ! 给它 E1 类型

route-map REDIST-TO-OSPF permit 30
 match tag 400                          ! 来自 BGP
 set metric 500                         ! 给它更差的 metric

route-map REDIST-TO-OSPF permit 40
 set tag 200                            ! 其他，标记为来自 EIGRP
```

**Tag 值的规划建议**（写进你的网络文档）：

| Tag | 含义 |
|:--|:--|
| 100 | 来自 OSPF |
| 200 | 来自 EIGRP |
| 300 | 来自静态路由 |
| 400 | 来自 BGP |
| 500 | 来自直连 |
| 999 | 禁止重分发 |

**实践建议**：**Route Tag 为主，必要时配合前缀过滤做二次保险**（纵深防御）。
</details>

**5.** PBR 的 `set ip next-hop` 和 `set ip default next-hop` 有什么区别？为什么 PBR 要配 track？

<details><summary>答案</summary>

## 两个 `set` 的区别

| 命令 | 优先级 | 行为 |
|:--|:--|:--|
| **`set ip next-hop`** | **PBR 优先于路由表** | 强制走这个下一跳，**即使路由表里有更好的路径** |
| **`set ip default next-hop`** | **路由表优先于 PBR** | **路由表里没有匹配的路由时**，才走这个下一跳 |

**决策流程对比**：

```
   set ip next-hop 10.0.22.1：
   
   包进来 → 匹配 route-map ？
              ├─ 是 → ★ 直接发给 10.0.22.1 ★（不看路由表）
              └─ 否 → 查路由表


   set ip default next-hop 10.0.22.1：
   
   包进来 → 匹配 route-map ？
              ├─ 是 → 先查路由表
              │        ├─ 有匹配的路由 → ★ 走路由表 ★
              │        └─ 没有         → 发给 10.0.22.1
              └─ 否 → 查路由表
```

**使用场景**：

| 场景 | 用哪个 |
|:--|:--|
| **强制某类流量走特定出口**（无论路由表怎么说） | `set ip next-hop` |
| **正常走路由表，只在没路由时用备用出口** | `set ip default next-hop` |
| 把访客流量强制导向特定的出口/防火墙 | `set ip next-hop` |
| 给某个网段配一个"兜底"的出口 | `set ip default next-hop` |

**类似的一对**：
- `set interface` vs `set ip default interface`（同样的优先级关系）

## 为什么 PBR 必须配 track

**因为 `set ip next-hop` 会强制走指定的下一跳，即使那个下一跳已经不可达。**

```
   PBR 配置：set ip next-hop 10.0.22.1
        ↓
   10.0.22.1 挂了（对端设备故障、链路断了）
        ↓
   ★ PBR 依然强制把流量发给它 ★
        ↓
   ★★★ 流量全部进黑洞 ★★★
        ↓
   而且【普通的路由收敛救不了】——因为 PBR 优先于路由表！
```

**这是 PBR 最危险的地方**：路由协议再怎么收敛，PBR 都无视它。

**解法：`verify-availability` + track**

```cisco
! ① 定义探测
R1(config)# ip sla 1
R1(config-ip-sla)#  icmp-echo 10.0.22.1
R1(config-ip-sla-echo)#   frequency 5
R1(config-ip-sla-echo)#   timeout 2000
R1(config)# ip sla schedule 1 life forever start-time now

R1(config)# ip sla 2
R1(config-ip-sla)#  icmp-echo 10.0.33.1
R1(config-ip-sla-echo)#   frequency 5
R1(config)# ip sla schedule 2 life forever start-time now

! ② 绑定 track（★ 加防抖）
R1(config)# track 1 ip sla 1 reachability
R1(config-track)#  delay down 10 up 30
R1(config)# track 2 ip sla 2 reachability
R1(config-track)#  delay down 10 up 30

! ③ PBR 挂钩 track，配多个备选
R1(config)# route-map PBR-POLICY permit 10
R1(config-route-map)#  match ip address FROM-SALES
R1(config-route-map)#  set ip next-hop verify-availability 10.0.22.1 1 track 1
R1(config-route-map)#  set ip next-hop verify-availability 10.0.33.1 2 track 2
!                                                            ↑        ↑    ↑
!                                                         下一跳    序号  track对象

R1(config)# route-map PBR-POLICY permit 20
! ★ 空 permit：所有 track 都 down 时，流量回落到正常路由表 ★
```

**行为**：
```
   track 1 up  → 走 10.0.22.1（序号 1，优先）
   track 1 down, track 2 up → 走 10.0.33.1（序号 2）
   两个都 down → ★ PBR 不生效，流量走正常路由表 ★
```

**验证**：
```cisco
R1# show route-map PBR-POLICY
route-map PBR-POLICY, permit, sequence 10
  Match clauses:
    ip address (access-lists): FROM-SALES
  Set clauses:
    ip next-hop verify-availability 10.0.22.1 1 track 1  ★ [up] ★
    ip next-hop verify-availability 10.0.33.1 2 track 2  [up]
  Policy routing matches: 1245 packets, 987654 bytes
                          ↑ 有命中说明 PBR 在工作

R1# show track brief
Track   Object                         Parameter        Value    Last Change
1       ip sla 1                       state            Up       00:15:23
2       ip sla 2                       state            Up       00:15:20
```

**测试黑洞保护**：
```cisco
R1(config)# interface GigabitEthernet0/2      ! 断掉第一个下一跳的链路
R1(config-if)# shutdown

! 等 10 秒（delay down 10）
R1# show route-map PBR-POLICY
    ip next-hop verify-availability 10.0.22.1 1 track 1  ★ [down] ★
    ip next-hop verify-availability 10.0.33.1 2 track 2  [up]
!                                              ↑ 自动切到序号 2 ✓
```

**PBR 的其他注意事项**：

**① 应用在【入接口】**
```cisco
R1(config)# interface GigabitEthernet0/0        ← 流量【进来】的接口
R1(config-if)# ip policy route-map PBR-POLICY
```
配在出接口是无效的（那时候转发决策已经做完了）。

**② 对路由器自己产生的流量要单独配**
```cisco
R1(config)# ip local policy route-map PBR-POLICY
```
比如你想让路由器自己发的 SNMP Trap 走特定出口。

**③ 性能考量**
早期 IOS 的 PBR 走 process switching（软件转发），性能差。现代平台大多支持 **CEF 加速的 PBR**：
```cisco
R1# show ip policy
R1# show ip cef <目的IP>
```
但复杂的 match 条件仍可能下沉到 CPU。**大流量场景要评估。**

**④ 永远加兜底的 permit**
```cisco
route-map PBR-POLICY permit 20
! 空的 permit = 其余流量走正常路由表
```
**不加的话，不匹配的流量会被 route-map 的隐含 deny 拦掉吗？**

**不会。** PBR 的行为特殊：**不匹配任何 route-map 语句的流量，走正常路由表**（不是被丢弃）。

但**匹配了 `deny` 语句的流量**，也是走正常路由表。

所以 PBR 的 route-map 里，`deny` 的含义是"**这些流量不做策略路由，走正常路由表**"，而不是"丢弃"。**这和 BGP/重分发里的 route-map 语义不同，容易混淆。**

```cisco
! PBR 中排除某些流量
route-map PBR-POLICY deny 5
 match ip address CRITICAL-TRAFFIC      ! 关键流量不做 PBR，走正常路由
route-map PBR-POLICY permit 10
 match ip address FROM-SALES
 set ip next-hop 10.0.22.1
```
</details>
