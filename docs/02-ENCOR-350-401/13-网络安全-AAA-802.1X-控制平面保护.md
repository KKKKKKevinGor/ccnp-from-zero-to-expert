# 13 · 网络安全：AAA / 802.1X / 控制平面保护

> **ENCOR 考纲权重 20%，仅次于基础设施（30%）。**

## ① 这章解决什么问题

三个真实的安全问题：

1. **设备管理**：10 个网工共用一个 `admin` 密码。有人改错了配置，**查不出是谁**；有人离职了，**要改所有设备的密码**。
2. **终端接入**：会议室的网口任何人插上就能进内网。访客、外包、甚至攻击者都能直接接入。
3. **设备自身**：有人对核心路由器发起 SSH 暴力破解，或者伪造大量 ARP，**把路由器的 CPU 打满**——设备"没被攻破"，但已经没法工作了。

对应的三个解法：**AAA、802.1X、控制平面保护（CoPP/CPPr）**。

## ② AAA：设备管理的三要素

### 2.1 三个 A 分别是什么

| A | 全称 | 回答的问题 | 例子 |
|:--|:--|:--|:--|
| **Authentication** | 认证 | **你是谁？** | 用户名 + 密码 / 证书 |
| **Authorization** | 授权 | **你能做什么？** | 只能 `show`，不能 `configure` |
| **Accounting** | 计费/审计 | **你做了什么？** | 记录每一条执行的命令 |

### 2.2 TACACS+ vs RADIUS（★ 高频考点）

| | **TACACS+** | **RADIUS** |
|:--|:--|:--|
| 标准 | **Cisco 私有** | **IETF 标准 (RFC 2865)** |
| 传输 | **TCP 49** | **UDP 1812（认证）/ 1813（计费）** |
| 加密 | ✅ **加密整个报文体** | ❌ **只加密密码字段**，其余明文 |
| AAA 分离 | ✅ **认证/授权/计费完全分离** | ❌ **认证和授权合并** |
| **命令级授权** | ✅ **支持**（可精确控制每条命令） | ❌ **不支持** |
| 多协议支持 | ✅ 支持非 IP 协议 | 只支持 IP |
| 典型用途 | ★ **设备管理（网工登录）** | ★ **终端接入（802.1X、VPN、无线）** |

**选型原则（一句话）**：
> **管设备用 TACACS+，管用户用 RADIUS。**

**为什么设备管理用 TACACS+**：
1. **命令级授权** —— 可以精确控制"实习生只能敲 show 命令，不能 configure"
2. **加密整个报文** —— RADIUS 只加密密码，用户名和授权信息明文传输
3. **AAA 分离** —— 认证通过后，每条命令都可以单独去服务器授权

**为什么终端接入用 RADIUS**：
1. **802.1X 标准规定用 RADIUS**（EAP over RADIUS）
2. 标准协议，各厂商设备和 NAC 系统都支持
3. 可以返回丰富的属性（VLAN、ACL、SGT、限速）

### 2.3 AAA 配置

```cisco
! ═══ ① 启用 AAA ═══
R1(config)# aaa new-model
! ⚠️ 这条命令会立即改变认证行为！配置前必须确保有本地账号，否则可能被锁在门外

! ═══ ② 本地账号（保底，★ 必须先配）═══
R1(config)# username emergency-admin privilege 15 secret Str0ngP@ssw0rd!

! ═══ ③ TACACS+ 服务器 ═══
R1(config)# tacacs server ISE-01
R1(config-server-tacacs)#  address ipv4 10.1.30.70
R1(config-server-tacacs)#  key TacacsSharedSecret
R1(config-server-tacacs)#  timeout 5
R1(config-server-tacacs)#  single-connection

R1(config)# tacacs server ISE-02
R1(config-server-tacacs)#  address ipv4 10.1.30.71
R1(config-server-tacacs)#  key TacacsSharedSecret

R1(config)# aaa group server tacacs+ TACACS-GROUP
R1(config-sg-tacacs+)#  server name ISE-01
R1(config-sg-tacacs+)#  server name ISE-02
R1(config-sg-tacacs+)#  ip tacacs source-interface Loopback0

! ═══ ④ 认证 ═══
! 登录认证：先试 TACACS+，失败（服务器不可达）则用本地
R1(config)# aaa authentication login default group TACACS-GROUP local
!                                                                  ↑ ★ 保底
! enable 认证
R1(config)# aaa authentication enable default group TACACS-GROUP enable

! ═══ ⑤ 授权 ═══
! EXEC 授权（决定登录后的权限级别）
R1(config)# aaa authorization exec default group TACACS-GROUP local if-authenticated

! 命令级授权（★ TACACS+ 独有）
R1(config)# aaa authorization commands 1 default group TACACS-GROUP if-authenticated
R1(config)# aaa authorization commands 15 default group TACACS-GROUP if-authenticated
R1(config)# aaa authorization config-commands

! ═══ ⑥ 计费（审计）═══
R1(config)# aaa accounting exec default start-stop group TACACS-GROUP
R1(config)# aaa accounting commands 1 default start-stop group TACACS-GROUP
R1(config)# aaa accounting commands 15 default start-stop group TACACS-GROUP
R1(config)# aaa accounting system default start-stop group TACACS-GROUP

! ═══ ⑦ 应用到线路 ═══
R1(config)# line vty 0 15
R1(config-line)#  transport input ssh
R1(config-line)#  exec-timeout 10 0
R1(config)# line console 0
R1(config-line)#  exec-timeout 15 0

! ═══ 查看与测试 ═══
R1# show aaa servers
R1# show tacacs
R1# test aaa group TACACS-GROUP <username> <password> legacy    ! ★ 测试连通性
R1# show aaa sessions
R1# debug aaa authentication
R1# debug tacacs
```

> ⚠️ **`aaa new-model` 的危险性**：这条命令**立即生效**，会改变所有线路的认证行为。
>
> **配置前的安全流程**：
> ```cisco
> ! ① 先建本地账号
> R1(config)# username emergency-admin privilege 15 secret Str0ngP@ssw0rd!
>
> ! ② 保存配置（可以 reload 回滚）
> R1# write memory
>
> ! ③ 设置保险绳
> R1# configure terminal revert timer 10
>
> ! ④ 再启用 AAA
> R1(config)# aaa new-model
> R1(config)# aaa authentication login default group TACACS-GROUP local
> !                                                                  ↑ 保底不能少
> ! ⑤ 【另开一个会话】测试能否登录
> ! ⑥ 确认无误
> R1# configure confirm
> R1# write memory
> ```
>
> **`local` 保底的重要性**：如果 TACACS+ 服务器挂了或网络不通，没有 `local` 保底的话，**所有人都登不上设备**。这在服务器故障时会变成灾难。

### 2.4 特权级别

Cisco 有 **0–15** 共 16 个特权级别：

| 级别 | 说明 |
|:--|:--|
| **0** | 极少数命令（`logout`、`enable`、`disable`、`help`、`exit`） |
| **1** | **用户模式**（默认，只能 `show` 部分命令） |
| 2–14 | **自定义**（可以把特定命令分配到这些级别） |
| **15** | **特权模式**（完全控制） |

```cisco
! 自定义级别 5：允许配置接口但不能做别的
R1(config)# privilege exec level 5 configure terminal
R1(config)# privilege configure level 5 interface
R1(config)# privilege interface level 5 shutdown
R1(config)# privilege interface level 5 no shutdown
R1(config)# privilege exec level 5 show running-config

R1(config)# username junior privilege 5 secret JuniorPass
R1(config)# enable secret level 5 Level5Pass
```

> **实践中更推荐用 TACACS+ 的命令级授权**，而不是本地特权级别。因为：
> - 特权级别配置繁琐且分散在每台设备上
> - TACACS+ 可以集中定义策略，一处修改全网生效
> - 可以做更精细的控制（正则匹配命令参数）

## ③ 802.1X：终端接入控制

### 3.1 三个角色

```
   [请求者 Supplicant]    [认证者 Authenticator]    [认证服务器 Auth Server]
      PC / 手机       ←→     交换机 / AP        ←→      RADIUS (ISE/NPS)
          │                       │                        │
          └───── EAPOL ───────────┘                        │
                （二层协议）        └──── RADIUS (UDP 1812) ─┘
```

| 角色 | 职责 |
|:--|:--|
| **Supplicant** | 终端上的软件（Windows 内置、wpa_supplicant） |
| **Authenticator** | 交换机/AP，**只是中继**，不做认证决策 |
| **Authentication Server** | RADIUS 服务器（Cisco ISE、Windows NPS、FreeRADIUS） |

### 3.2 认证流程

```
① 端口初始状态：★ 未授权 ★，只允许 EAPOL / CDP / STP 通过
        ↓
② 交换机发 EAP-Request/Identity
        ↓
③ PC 回 EAP-Response/Identity（用户名）
        ↓
④ 交换机封装成 RADIUS Access-Request 转发给 RADIUS 服务器
        ↓
⑤ RADIUS 与 PC 进行 EAP 方法协商（PEAP / EAP-TLS）
   （交换机只是中继，不参与）
        ↓
⑥ 认证通过 → RADIUS 返回 Access-Accept
   ★ 可携带属性：VLAN、ACL、SGT、限速 ★
        ↓
⑦ 交换机把端口置为【已授权】，应用下发的策略
```

### 3.3 EAP 方法对比

| 方法 | 客户端凭据 | 服务器证书 | 客户端证书 | 安全性 | 部署难度 |
|:--|:--|:--|:--|:--|:--|
| **EAP-TLS** | **证书** | ✅ 需要 | ✅ **需要** | ★★★★★ | 高（要建 PKI） |
| **PEAP-MSCHAPv2** | 用户名/密码 | ✅ 需要 | ❌ | ★★★★ | ★ **中（最常用）** |
| EAP-TTLS | 用户名/密码 | ✅ 需要 | ❌ | ★★★★ | 中 |
| EAP-FAST | PAC 文件 | 可选 | ❌ | ★★★ | Cisco 私有 |
| EAP-MD5 | 用户名/密码 | ❌ | ❌ | ★ | ❌ **禁用**（明文哈希，可破解） |

**选型建议**：
- **大多数企业：PEAP-MSCHAPv2** —— 直接对接 AD，用户用域账号登录，不需要给每台设备发证书
- **高安全要求：EAP-TLS** —— 最安全，但需要 PKI 基础设施和证书生命周期管理

! 协议

SW1(config-if-range)# spanning-tree bpduguard enable

### 3.5 host-mode 四种模式（★ 考点）

| 模式 | 允许的设备 | 说明 | 用途 |
|:--|:--|:--|:--|
| `single-host` | **1 个 MAC** | 最严格 | 高安全区域 |
| `multi-host` | 第一个认证通过后，**后续全部放行** | ⚠️ **不安全** | 不推荐 |
| **`multi-domain`** | **1 个数据域 + 1 个语音域** | ★ **最常用** | PC + IP 电话 |
| `multi-auth` | **每个 MAC 独立认证** | 最灵活 | 端口下接 HUB / 虚拟机 |

> **`multi-host` 的安全隐患**：一旦有一个设备认证成功，端口就完全开放。攻击者可以在合法用户认证后接一台 HUB 进来，绕过所有认证。**不要用。**

### 3.6 MAB（MAC Authentication Bypass）

**问题**：打印机、摄像头、门禁、老式设备不支持 802.1X 怎么办？

**MAB**：用设备的 **MAC 地址**作为用户名和密码，在 RADIUS 上做认证。

```cisco
SW1(config-if)# mab
SW1(config-if)# authentication order dot1x mab      ! 先试 802.1X，超时后试 MAB
SW1(config-if)# authentication priority dot1x mab
```

**流程**：
```
① 交换机先尝试 802.1X（发 EAP-Request/Identity）
② 等待 tx-period × max-reauth-req 秒（默认 30×2=60 秒）没有响应
③ 判定"这个设备不支持 802.1X"
④ 抓取它的源 MAC，用 MAC 作为用户名/密码发 RADIUS 请求
⑤ RADIUS 查白名单，匹配则授权
```

**缩短等待时间**（否则打印机要等 60 秒才能上网）：
```cisco
SW1(config-if)# dot1x timeout tx-period 7
SW1(config-if)# dot1x max-reauth-req 2
! 7 × 2 = 14 秒后转 MAB
```

> ⚠️ **MAB 的安全性很弱**：MAC 地址可以轻易伪造。攻击者只要知道一台打印机的 MAC，就能伪装成它接入网络。
>
> **加固手段**：
> - 配合 **Profiling**（ISE 通过 DHCP、HTTP User-Agent、CDP/LLDP 等指纹判断设备类型），发现"MAC 是打印机但行为像 PC"就拒绝
> - 给 MAB 设备下发**严格的 ACL**（打印机只能被访问 9100 端口，不能主动访问其他网段）
> - 定期审计 MAB 白名单

### 3.7 RADIUS 服务器不可达时的处理（★ 实战关键）

**如果 RADIUS 挂了，所有端口都认证失败 → 全公司断网。这是不可接受的。**

```cisco
! ① 探测 RADIUS 存活
SW1(config)# radius server ISE-01
SW1(config-radius-server)#  automate-tester username probe-user probe-on
SW1(config-radius-server)#  deadtime 10

! ② Critical Authentication：RADIUS 死了就放行到指定 VLAN
SW1(config-if)# authentication event server dead action authorize vlan 10
SW1(config-if)# authentication event server dead action authorize voice
SW1(config-if)# authentication event server alive action reinitialize
```

**行为**：
- RADIUS 可达 → 正常认证
- **RADIUS 不可达 → 端口自动授权到 VLAN 10**（业务不中断）
- RADIUS 恢复 → **自动重新认证**

> **这是 802.1X 部署的必配项**。没有它，一次 RADIUS 故障就是全公司级的网络中断事故。

## ④ 控制平面保护

### 4.1 数据平面 vs 控制平面 vs 管理平面

| 平面 | 处理什么 | 谁处理 |
|:--|:--|:--|
| **数据平面** | 用户流量的转发 | **ASIC 硬件**（快） |
| **控制平面** | **路由协议、ARP、STP、ICMP、SSH** | **CPU**（慢） |
| **管理平面** | SSH/Telnet/SNMP/NetFlow | CPU |

**攻击原理**：

```
   正常：用户流量 → ASIC 硬件转发 → 出去（CPU 不参与）
   
   攻击：攻击者发送大量【必须由 CPU 处理】的包
         · 大量 ARP 请求
         · 大量 TTL=1 的包（触发 ICMP Time Exceeded）
         · 大量带 IP Options 的包
         · 大量 SSH 连接请求
         · 伪造的路由协议报文
              ↓
         ★ CPU 被打满 ★
              ↓
         · 路由协议 Hello 处理不过来 → 邻居断开
         · SSH 登不上去 → 无法管理
         · 整台设备失去响应
         
   设备"没被攻破"，但已经瘫痪了。
```

### 4.2 CoPP（Control Plane Policing）

**给送往 CPU 的流量做 QoS 限速。**

```cisco
! ═══ ① 分类：定义各类控制平面流量 ═══
! 路由协议（最高优先，绝不能限）
SW1(config)# ip access-list extended ACL-ROUTING
SW1(config-ext-nacl)#  permit ospf any any
SW1(config-ext-nacl)#  permit eigrp any any
SW1(config-ext-nacl)#  permit tcp any any eq 179          ! BGP
SW1(config-ext-nacl)#  permit tcp any eq 179 any
SW1(config-ext-nacl)#  permit pim any any
SW1(config-ext-nacl)#  permit igmp any any

! 管理流量
SW1(config)# ip access-list extended ACL-MANAGEMENT
SW1(config-ext-nacl)#  permit tcp 10.1.30.0 0.0.0.255 any eq 22
SW1(config-ext-nacl)#  permit udp 10.1.30.0 0.0.0.255 any eq snmp
SW1(config-ext-nacl)#  permit udp any any eq ntp

! ICMP
SW1(config)# ip access-list extended ACL-ICMP
SW1(config-ext-nacl)#  permit icmp any any echo
SW1(config-ext-nacl)#  permit icmp any any echo-reply
SW1(config-ext-nacl)#  permit icmp any any ttl-exceeded
SW1(config-ext-nacl)#  permit icmp any any unreachable

! 明确要丢弃的
SW1(config)# ip access-list extended ACL-UNDESIRABLE
SW1(config-ext-nacl)#  permit tcp any any eq 23           ! Telnet
SW1(config-ext-nacl)#  permit udp any any eq 69           ! TFTP

! ═══ ② class-map ═══
SW1(config)# class-map match-all COPP-ROUTING
SW1(config-cmap)#  match access-group name ACL-ROUTING
SW1(config)# class-map match-all COPP-MANAGEMENT
SW1(config-cmap)#  match access-group name ACL-MANAGEMENT
SW1(config)# class-map match-all COPP-ICMP
SW1(config-cmap)#  match access-group name ACL-ICMP
SW1(config)# class-map match-all COPP-UNDESIRABLE
SW1(config-cmap)#  match access-group name ACL-UNDESIRABLE

! ═══ ③ policy-map ═══
SW1(config)# policy-map COPP-POLICY
SW1(config-pmap)# class COPP-ROUTING
SW1(config-pmap-c)#  police 8000000 conform-action transmit exceed-action transmit
!                    ↑ 路由协议：不限速（只监控）★ 绝不能限死路由协议

SW1(config-pmap)# class COPP-MANAGEMENT
SW1(config-pmap-c)#  police 500000 conform-action transmit exceed-action drop

SW1(config-pmap)# class COPP-ICMP
SW1(config-pmap-c)#  police 100000 conform-action transmit exceed-action drop

SW1(config-pmap)# class COPP-UNDESIRABLE
SW1(config-pmap-c)#  police 8000 conform-action drop exceed-action drop
!                                                ↑ 直接丢

SW1(config-pmap)# class class-default
SW1(config-pmap-c)#  police 200000 conform-action transmit exceed-action drop

! ═══ ④ 应用到控制平面 ═══
SW1(config)# control-plane
SW1(config-cp)#  service-policy input COPP-POLICY

! ═══ 查看 ═══
SW1# show policy-map control-plane
SW1# show policy-map control-plane input class COPP-ICMP
```

> ⚠️ **CoPP 配置的最大风险：把自己锁死。**
>
> 如果把 SSH 或路由协议限得太狠，或者 ACL 写错导致合法流量落进了 `class-default` 被丢弃，你会**失去对设备的管理**，同时**路由协议邻居全断**。
>
> **安全部署流程**：
> ```cisco
> ! ① 先用【只监控不丢弃】的策略跑一周，收集基线
> policy-map COPP-MONITOR
>  class COPP-ROUTING
>   police 8000000 conform-action transmit exceed-action transmit
>  class COPP-MANAGEMENT
>   police 500000 conform-action transmit exceed-action transmit   ← 都是 transmit
>  ...
>
> ! ② 一周后看实际流量
> SW1# show policy-map control-plane
>
> ! ③ 根据实际值设定阈值（留 2-3 倍余量）
> ! ④ 再改成 exceed-action drop
> ! ⑤ 用 configure revert timer 做保险
> ```

### 4.3 CPPr（Control Plane Protection）—— 更精细

CPPr 把控制平面细分为三个子接口，可以分别做策略：

| 子接口 | 处理什么 |
|:--|:--|
| **Host** | 目的是路由器自身的流量（SSH、SNMP、路由协议） |
| **Transit** | 需要 CPU 处理但要转发出去的（IP Options、非 CEF 转发） |
| **CEF-Exception** | TTL 超时、ARP、无法 CEF 转发的 |

```cisco
R1(config)# control-plane host
R1(config-cp-host)#  service-policy input COPP-HOST-POLICY
R1(config)# control-plane transit
R1(config-cp-transit)#  service-policy input COPP-TRANSIT-POLICY
R1(config)# control-plane cef-exception
R1(config-cp-cef)#  service-policy input COPP-CEF-POLICY
```

### 三厂商对照

| 目的 | Cisco | H3C | 华为 |
|:--|:--|:--|:--|
| 启用 AAA | `aaa new-model` | 默认启用 | 默认启用 |

| TACACS+ | `tacacs server NAME` | `hwtacacs scheme NAME` | `hwtacacs-server template NAME` |
| 认证方案 | `aaa authentication login default group X local` | `domain X` + `authentication login radius-scheme Y local` | `aaa` + `authentication-scheme X` |
| 802.1X 全局 | `dot1x system-auth-control` | `dot1x` | `dot1x enable` |
| 802.1X 端口 | `authentication port-control auto` | `dot1x port-control auto` | `dot1x enable`（接口下） |
| MAB | `mab` | `mac-authentication` | `mac-authen` |
| CoPP | `control-plane` + `service-policy` | `control-plane slot X` + `qos apply policy` | CPU 防攻击策略 `cpu-defend policy` |
| DHCP Snooping | `ip dhcp snooping` | `dhcp snooping enable` | `dhcp snooping enable` |
| DAI | `ip arp inspection vlan X` | `arp detection enable` | `arp anti-attack check user-bind enable` |
| 查会话 | `show authentication sessions` | `display dot1x` | `display dot1x` |

### 考点

- **TACACS+ vs RADIUS**：TCP49/加密全部/支持命令授权 vs UDP1812/只加密密码/不支持命令授权
- **AAA 三要素**
- **`aaa authentication login default group X local`** 的 `local` 保底
- **802.1X 三个角色 + host-mode 四种模式**
- **MAB 的用途和安全弱点**
- **Critical Authentication（RADIUS 死了的降级）**
- **CoPP 保护控制平面 CPU**
- **DHCP Snooping → DAI → IPSG 的依赖链**

### 自测题

**1.** TACACS+ 和 RADIUS 有什么区别？分别用在什么场景？

<details><summary>答案</summary>

| | **TACACS+** | **RADIUS** |
|:--|:--|:--|
| 标准 | **Cisco 私有** | **IETF 标准 (RFC 2865)** |
| 传输 | **TCP 49** | **UDP 1812（认证）/ 1813（计费）** |
| 加密 | ✅ **加密整个报文体** | ❌ **只加密密码字段** |
| AAA 分离 | ✅ **完全分离** | ❌ 认证和授权合并 |
| **命令级授权** | ✅ **支持** | ❌ **不支持** |
| 典型用途 | ★ **设备管理** | ★ **终端接入** |

**选型口诀：管设备用 TACACS+，管用户用 RADIUS。**

**为什么设备管理必须用 TACACS+**：

**① 命令级授权（最关键的能力）**
```
   实习生登录 → 只允许执行 show 命令
   初级工程师 → 允许配置接口，但不允许 reload、不允许改路由
   高级工程师 → 完全权限
```
TACACS+ 的每一条命令都可以单独发到服务器授权。RADIUS 做不到——它只能在认证时返回一个权限级别，之后就管不着了。

**② 加密整个报文**
RADIUS 只加密密码字段，**用户名、授权信息、计费数据全是明文**。抓包就能看到"谁在什么时候登录了哪台设备"。TACACS+ 加密整个报文体。

**③ AAA 完全分离**
可以用不同的服务器分别做认证、授权、计费；也可以只用其中一部分。

**为什么终端接入必须用 RADIUS**：

**① 802.1X 标准就是基于 RADIUS 的**（EAP over RADIUS，RFC 3579）。这是硬性规定。

**② 标准协议，生态成熟**：所有厂商的交换机、AP、VPN 网关、NAC 系统都支持 RADIUS。

**③ 可以返回丰富的属性**：
```
Access-Accept 里可以携带：
  · Tunnel-Private-Group-ID → 动态 VLAN
  · Filter-Id / cisco-av-pair → 动态 ACL
  · Cisco-AVPair: cts:security-group-tag → SGT
  · Session-Timeout → 会话超时
  · 限速属性
```

**④ 支持 CoA（Change of Authorization）**：认证后还能动态改变策略（比如检测到终端中毒，立即把它隔离到 quarantine VLAN）。

**实际部署的典型架构**：
```
   ┌──────────────────────────────────┐
   │      Cisco ISE（一台服务器）        │
   │  · TACACS+ 服务（管设备）           │
   │  · RADIUS 服务（管终端）            │
   │  · 对接 AD 做用户认证               │
   └───────┬──────────────────┬────────┘
           │ TACACS+ (TCP 49) │ RADIUS (UDP 1812)
           ↓                  ↓
   [网工登录设备]        [员工接入网络]
```

一台 ISE 同时提供两种服务，共用 AD 用户库。这是企业标准做法。
</details>

**2.** 配 AAA 时为什么必须写 `local` 保底？不写会怎样？

<details><summary>答案</summary>

```cisco
R1(config)# aaa authentication login default group TACACS-GROUP local
!                                                                  ↑ 这个 local
```

**`local` 是【方法列表】的第二个方法**：先尝试 TACACS+，**如果 TACACS+ 服务器不可达**，就用本地账号认证。

**不写会怎样**：

```cisco
R1(config)# aaa authentication login default group TACACS-GROUP
!                                                              ↑ 没有保底
```

**TACACS+ 服务器一旦不可达**（服务器宕机、网络中断、密钥配错、ACL 拦了 TCP 49）：
```
   ★ 所有人都登不上这台设备 ★
   · SSH 登不上
   · Console 也登不上（因为 default 方法列表也应用到 console）
   · 只能物理接触设备做密码恢复（configure register 0x2142 + 重启）
```

**如果这台设备在异地机房，或者同时有几十台设备受影响 —— 这就是重大事故。**

**关键理解：什么情况下会 fallback 到 `local`**

| 情况 | 行为 |
|:--|:--|
| **TACACS+ 服务器不可达**（超时/网络不通） | ✅ **fallback 到 local** |
| **TACACS+ 服务器可达，但拒绝了这个用户** | ❌ **不 fallback**，直接拒绝 |

**这个区分很重要**：`local` 不是"TACACS+ 说不行我就用本地试试"（那样就绕过了集中认证），而是"TACACS+ 联系不上时的应急通道"。

**完整的安全配置模板**：
```cisco
! ① 先建本地应急账号（★ 必须在启用 AAA 之前）
R1(config)# username emergency-admin privilege 15 secret Str0ngComplexP@ssw0rd!

! ② 保存配置（这样 reload 能回滚）
R1# write memory

! ③ 设置保险绳
R1# configure terminal revert timer 10

! ④ 启用 AAA
R1(config)# aaa new-model

! ⑤ 所有方法列表都要有 local 保底
R1(config)# aaa authentication login default group TACACS-GROUP local
R1(config)# aaa authentication enable default group TACACS-GROUP enable
R1(config)# aaa authorization exec default group TACACS-GROUP local if-authenticated
R1(config)# aaa authorization commands 15 default group TACACS-GROUP if-authenticated
!                                                                    ↑ 服务器不可达时放行已认证用户

! ⑥ 【另开一个 SSH 会话】测试能否登录
! ⑦ 确认无误
R1# configure confirm
R1# write memory
```

**`if-authenticated` 的作用**：授权时如果服务器不可达，**只要用户已经通过了认证，就允许执行命令**。没有它的话，即使用 local 登录成功了，每条命令都会因为无法授权而被拒绝。

**⚠️ `aaa new-model` 的即时生效性**：这条命令**立即改变所有线路的认证行为**。在远程会话中敲下这条命令的瞬间，如果后续配置来不及跟上，你可能就断连了。

**所以标准流程是**：本地账号 → 保存 → revert 保险 → 启用 AAA → 配完整方法列表 → 另开会话验证 → confirm。

**本地应急账号的管理**：
- 密码要**足够复杂**（它是最后的防线）
- **定期轮换**（写进运维流程）
- 密码存放在**密码管理系统**里，多人可取
- 可以考虑用 `username X privilege 15 secret` 配合 `access-class` 限制来源
</details>

**3.** 802.1X 部署后，RADIUS 服务器宕机了会发生什么？怎么避免？

<details><summary>答案</summary>

**默认行为：所有端口认证失败 → 全公司断网。**

因为交换机拿不到 Access-Accept，端口保持**未授权**状态，只允许 EAPOL 帧通过，业务流量全部被阻断。

**这是 802.1X 部署最大的风险。** 一次 RADIUS 故障 = 全公司级的网络中断。

**解决方案：Critical Authentication（关键认证）**

```cisco
! ① 让交换机主动探测 RADIUS 是否存活
SW1(config)# radius server ISE-01
SW1(config-radius-server)#  address ipv4 10.1.30.70 auth-port 1812 acct-port 1813
SW1(config-radius-server)#  key RadiusSecret
SW1(config-radius-server)#  automate-tester username probe-user probe-on
SW1(config-radius-server)#  deadtime 10

! ② 配置服务器死亡时的降级策略
SW1(config)# interface range GigabitEthernet1/0/1-20
SW1(config-if-range)# authentication event server dead action authorize vlan 10
SW1(config-if-range)# authentication event server dead action authorize voice
SW1(config-if-range)# authentication event server alive action reinitialize
```

**行为**：

| 状态 | 行为 |
|:--|:--|
| RADIUS 可达 | 正常 802.1X 认证 |
| **RADIUS 不可达** | **端口自动授权到 VLAN 10（业务 VLAN），业务不中断** ✓ |
| RADIUS 恢复 | **自动触发重新认证**，回到正常流程 ✓ |

**验证**：
```cisco
SW1# show aaa servers | include State
     State: current DEAD, duration 45s

SW1# show authentication sessions interface Gi1/0/5 details
Status:  Authorized
Method status list:
   Method      State
   dot1x       Authc Success (Critical)          ← ★ Critical Auth 生效
Server Policies:
   Vlan Group:  Vlan: 10                         ← 依然在业务 VLAN ✓
```

**完整的高可用设计**：

**① RADIUS 服务器冗余（至少两台）**
```cisco
SW1(config)# aaa group server radius RADIUS-GROUP
SW1(config-sg-radius)#  server name ISE-01
SW1(config-sg-radius)#  server name ISE-02
SW1(config-sg-radius)#  deadtime 10                 ! 标记死亡的服务器 10 分钟不再尝试
```

**② 两台 ISE 部署在不同的物理位置**（不同机房/机柜/电源）

**③ 主动探测（automate-tester）**
```cisco
SW1(config-radius-server)#  automate-tester username probe-user probe-on
```
交换机周期性用一个测试账号探测 RADIUS。**不配的话，交换机只有在真实认证请求超时时才知道服务器挂了**——那时候用户已经受影响了。

**④ Critical VLAN 的选择**

| 方案 | 说明 |
|:--|:--|
| **降级到业务 VLAN** | 业务完全不受影响，但安全性暂时归零 |
| **降级到受限 VLAN** | 只能访问核心服务（DNS/邮件），安全性折中 |

**选哪个取决于你的风险偏好**。多数企业选前者——**RADIUS 故障是运维问题，不应该变成业务事故**。

**⑤ 分阶段部署（★ 最重要的实践）**

**永远不要一上来就开启强制认证。** 标准流程：

```
阶段 1：Monitor Mode（监控模式，不阻断）
   authentication open                          ← ★ 端口开放，只记录认证结果
   → 跑 1-2 个月，收集数据，发现所有不支持 802.1X 的设备

阶段 2：Low Impact Mode（低影响模式）
   authentication open
   ip access-group PRE-AUTH-ACL in              ← 认证前只允许 DHCP/DNS/AD
   → 认证通过后 RADIUS 下发完整 ACL

阶段 3：Closed Mode（强制模式）
   no authentication open                       ← 完全阻断
   → 确认所有设备都能正常认证后才切换
```

**在阶段 1 就能发现所有问题设备**（老打印机、监控摄像头、门禁、扫码枪、工业设备），提前配好 MAB 白名单，避免正式启用时的大面积故障。

**部署检查清单**：
```
□ ① 至少两台 RADIUS 服务器，异地部署
□ ② automate-tester 主动探测
□ ③ Critical Authentication 配置
□ ④ 所有不支持 802.1X 的设备已加入 MAB 白名单
□ ⑤ 经历过 Monitor Mode 阶段
□ ⑥ NTP 同步（证书验证依赖）
□ ⑦ 演练过 RADIUS 故障场景
```
</details>

**4.** 什么是 CoPP？为什么需要它？配置时最大的风险是什么？

<details><summary>答案</summary>

**CoPP (Control Plane Policing) = 给"送往 CPU 处理的流量"做 QoS 限速。**

**为什么需要**：

网络设备的转发分两条路径：
```
   数据平面：用户流量 → ★ ASIC 硬件转发 ★ → 出去（线速，CPU 不参与）
   
   控制平面：某些包必须由 ★ CPU ★ 处理
             · 路由协议报文（OSPF Hello、BGP Update）
             · ARP 请求/响应
             · 目的是设备自身的包（SSH、SNMP、ping 路由器）
             · TTL=1 的包（要回 ICMP Time Exceeded）
             · 带 IP Options 的包
             · 无法 CEF 转发的包
```

**攻击原理**：攻击者不需要"攻破"设备，只需要**发送大量必须由 CPU 处理的包**：

```
   大量伪造的 ARP 请求
   大量 TTL=1 的包
   大量 SSH 连接尝试
   大量带 IP Options 的包
        ↓
   ★ CPU 100% ★
        ↓
   · 路由协议 Hello 处理不过来 → 邻居超时断开 → 路由震荡
   · SSH 登不上 → 完全失去管理能力
   · 整台设备失去响应
```

**设备"没被入侵"，但已经完全瘫痪。** 而且这种攻击门槛极低——一个脚本就能做到。

**CoPP 的作用**：给不同类型的控制平面流量分配带宽上限，**保证关键流量（路由协议）永远有资源，限制可疑流量**。

```cisco
control-plane
 service-policy input COPP-POLICY
```

**★ 最大的风险：把自己锁死。**

```
   如果 SSH 被限得太狠 → ★ 你登不上设备了 ★
   如果路由协议被限速 → ★ 邻居全断，网络瘫痪 ★
   如果 ACL 写错，合法流量落进 class-default 被丢 → 同上
```

**而且这个后果是【立即的、全局的】**——一条命令下去，可能整台设备就失联了。

**安全部署流程（★ 必须遵守）**：

**① 先用"只监控不丢弃"的策略收集基线（跑 1-2 周）**
```cisco
policy-map COPP-MONITOR
 class COPP-ROUTING
  police 8000000 conform-action transmit exceed-action transmit    ← 都是 transmit
 class COPP-MANAGEMENT
  police 500000 conform-action transmit exceed-action transmit
 class COPP-ICMP
  police 100000 conform-action transmit exceed-action transmit
 class class-default
  police 500000 conform-action transmit exceed-action transmit
```

**② 看实际流量，确定基线**
```cisco
SW1# show policy-map control-plane

    Class-map: COPP-ROUTING
      5 minute offered rate 12000 bps                 ← 实际只用 12kbps
    Class-map: COPP-ICMP
      5 minute offered rate 3000 bps                  ← 实际 3kbps
    Class-map: class-default
      5 minute offered rate 1000 bps
```

**③ 用实测值 × 2-3 倍作为正式阈值**

**④ 关键原则：路由协议永远不限速**
```cisco
policy-map COPP-POLICY
 class COPP-ROUTING
  police 8000000 conform-action transmit exceed-action transmit    ← ★ 永远 transmit
!                                                     ↑ 只监控，不丢弃
```
**宁可让路由协议占用 CPU，也不能因为限速导致邻居断开。** 路由协议流量本来就很小，正常情况不会超限；如果真超了，说明有异常，你需要的是告警而不是丢弃。

**⑤ 用 revert 保险绳部署**
```cisco
SW1# write memory
SW1# configure terminal revert timer 10
SW1(config)# control-plane
SW1(config-cp)#  service-policy input COPP-POLICY
SW1(config-cp)# end

! 立即验证
SW1# show ip ospf neighbor           ← 邻居还在吗？
SW1# show ip bgp summary             ← BGP 还在吗？
! 【另开一个 SSH 会话】测试能否登录

SW1# configure confirm               ! 确认无误
SW1# write memory
```

**⑥ 逐台部署，不要批量下发**
先在一台非核心设备上部署，观察一周，再推广。

**分类建议**：

| 类别 | 策略 | 理由 |
|:--|:--|:--|
| **路由协议**（OSPF/BGP/EIGRP/PIM） | **不限速**（只监控） | 断了就是灾难 |
| **管理流量**（SSH/SNMP/NTP） | 中等限速 + 源 ACL 限制 | 保证管理通道 |
| **ICMP** | 严格限速 | 常被用于攻击 |
| **明确不需要的**（Telnet/TFTP/小服务） | **直接丢弃** | 减少攻击面 |
| **class-default** | 限速 | 兜底 |

**监控**：
```cisco
SW1# show policy-map control-plane
! 定期检查 exceeded 计数，突然增长说明可能有攻击
```
</details>

**5.** DHCP Snooping、DAI、IPSG 三者是什么关系？

<details><summary>答案</summary>

**它们是一条依赖链，DHCP Snooping 是基础，DAI 和 IPSG 都依赖它建立的绑定表。**

```
   ┌─────────────────────────────────────────┐
   │      ★ DHCP Snooping ★                  │
   │  偷听 DHCP 报文，建立绑定表：             │
   │  MAC ↔ IP ↔ VLAN ↔ 端口 ↔ 租期           │
   └───────────────┬─────────────────────────┘
                   │ 提供数据基础
       ┌───────────┴───────────┐
       ↓                       ↓
   ┌───────────────┐   ┌───────────────────┐
   │  ★ DAI ★      │   │  ★ IPSG ★         │
   │ 动态ARP检测    │   │  IP 源防护         │
   │ 防 ARP 欺骗    │   │  防 IP 地址盗用     │
   └───────────────┘   └───────────────────┘
```

**① DHCP Snooping —— 基础**

**防什么**：
- 恶意 DHCP 服务器（DHCP Spoofing → 中间人攻击）
- DHCP 耗尽攻击（Starvation → 拒绝服务）

**怎么做**：把端口分为 trust（通往合法 DHCP 服务器）和 untrust（接终端）。**untrust 口不允许发 DHCP OFFER/ACK**。

**产出：绑定表**
```cisco
SW1# show ip dhcp snooping binding
MacAddress          IpAddress        Lease(sec)  Type           VLAN  Interface
------------------  ---------------  ----------  -------------  ----  --------------
00:50:56:AA:BB:CC   192.168.10.55    28234       dhcp-snooping  10    Gi1/0/5
00:11:22:33:44:55   192.168.10.66    28245       dhcp-snooping  10    Gi1/0/8
```

**这张表是后面两个功能的数据来源。**

**② DAI (Dynamic ARP Inspection) —— 防 ARP 欺骗**

**防什么**：攻击者发送伪造的 ARP 响应，声称"我是网关"，把流量引到自己这里做中间人攻击。

**怎么做**：检查每一个 ARP 报文，**对照 DHCP Snooping 绑定表**：
```
   收到 ARP：声称 "192.168.10.100 的 MAC 是 AA:BB:CC:DD:EE:FF"
        ↓
   查绑定表：192.168.10.100 对应的 MAC 是 00:50:56:11:22:33
        ↓
   ★ 不匹配 → 丢弃 + 告警 ★
```

```cisco
SW1(config)# ip arp inspection vlan 10,20,100
SW1(config)# ip arp inspection validate src-mac dst-mac ip
SW1(config)# interface GigabitEthernet1/0/48
SW1(config-if)# ip arp inspection trust                    ! 上联口设为信任
SW1(config)# interface range GigabitEthernet1/0/1-20
SW1(config-if-range)# ip arp inspection limit rate 15      ! 限速，防 ARP 泛洪
```

**③ IPSG (IP Source Guard) —— 防 IP 地址盗用**

**防什么**：用户手工把 IP 改成别人的（比如改成服务器的 IP，或者改成老板的 IP 来绕过 ACL）。

**怎么做**：在端口上自动生成 ACL，**只允许绑定表里记录的 IP（和 MAC）发包**。

```cisco
SW1(config)# interface range GigabitEthernet1/0/1-20
SW1(config-if-range)# ip verify source                     ! 只校验 IP
! 或
SW1(config-if-range)# ip verify source port-security       ! 同时校验 IP + MAC
```

**完整配置**：
```cisco
! ── 全局 ──
SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10,20,100
SW1(config)# no ip dhcp snooping information option        ! 某些环境需要关掉 Option 82

SW1(config)# ip arp inspection vlan 10,20,100
SW1(config)# ip arp inspection validate src-mac dst-mac ip

! ── 上联口（信任）──
SW1(config)# interface GigabitEthernet1/0/48
SW1(config-if)# ip dhcp snooping trust
SW1(config-if)# ip arp inspection trust

! ── 接入口 ──
SW1(config)# interface range GigabitEthernet1/0/1-20
SW1(config-if-range)# ip dhcp snooping limit rate 10
SW1(config-if-range)# ip arp inspection limit rate 15
SW1(config-if-range)# ip verify source

! ── err-disable 自动恢复 ──
SW1(config)# errdisable recovery cause arp-inspection
SW1(config)# errdisable recovery cause dhcp-rate-limit
SW1(config)# errdisable recovery interval 300
```

**⚠️ 部署顺序很重要**：

```
   ① 先开 DHCP Snooping，跑一段时间（至少一个 DHCP 租期）
      让绑定表填充完整
        ↓
   ② 检查绑定表是否覆盖了所有终端
      SW1# show ip dhcp snooping binding
        ↓
   ③ 为静态 IP 设备手工添加绑定（★ 关键）
      服务器、打印机、摄像头等不用 DHCP 的设备
        ↓
   ④ 再开 DAI
        ↓
   ⑤ 最后开 IPSG
```

**静态设备的手工绑定（最容易踩的坑）**：
```cisco
! DAI 的静态绑定（用 ARP ACL）
SW1(config)# arp access-list STATIC-DEVICES
SW1(config-arp-nacl)#  permit ip host 192.168.10.200 mac host 0011.2233.4455
SW1(config-arp-nacl)#  permit ip host 192.168.10.201 mac host 0011.2233.4456
SW1(config)# ip arp inspection filter STATIC-DEVICES vlan 10

! IPSG 的静态绑定
SW1(config)# ip source binding 0011.2233.4455 vlan 10 192.168.10.200 interface Gi1/0/30
```

**不做静态绑定的后果**：所有静态 IP 的设备（服务器、打印机、摄像头、门禁）**全部断网**，因为它们不在 DHCP Snooping 绑定表里。

**这是"开了 DAI 后一半设备断网"的典型原因。**

**部署检查清单**：
```
□ ① DHCP Snooping 先跑一个完整租期周期
□ ② 上联口和 DHCP 服务器直连口设为 trust
□ ③ 检查绑定表覆盖率
□ ④ 所有静态 IP 设备已手工绑定
□ ⑤ 逐 VLAN 灰度启用（不要 vlan 1-4094）
□ ⑥ 配置 err-disable 自动恢复
□ ⑦ 监控 %SW_DAI 和 %DHCP_SNOOPING 日志
```
</details>
