# 01 · 网络分层与数据封装

## ① 这章解决什么问题

你在浏览器地址栏敲了 `http://192.168.1.100`，按下回车。

从这一刻到服务器返回页面，中间发生了几十个步骤。如果你说不清这些步骤，那么当页面打不开时，你只能靠"重启试试"。而一个网络工程师和一个重启工的区别，就在于**能不能把这条链路拆成若干个可验证的环节，然后一个一个排除**。

这一章要建立的就是这个拆解框架。

---

## ② 原理讲透

### 2.1 为什么要分层

设想没有分层的世界：你写一个聊天软件，得自己处理"信号怎么在铜线上编码""数据丢了怎么重传""对方 IP 在哪""字符怎么编码"。换根网线从铜缆变光纤，整个软件重写。

分层解决的是**解耦**：每一层只跟相邻层打交道，通过固定接口交互。换网线只影响物理层，上层代码一行不改。

这就是为什么 Wi-Fi 和以太网上都能跑 HTTP —— 它们只是换了一二层，三层以上完全复用。

### 2.2 OSI 七层 vs TCP/IP 四层

| OSI 七层 | TCP/IP 模型 | 干什么 | 数据单位 (PDU) | 典型协议/设备 |
|:--|:--|:--|:--|:--|
| 7 应用层 | 应用层 | 给用户/程序提供网络接口 | 数据 Data | HTTP, DNS, SSH, FTP |
| 6 表示层 | 应用层 | 编码、加密、压缩 | 数据 | TLS, JPEG, ASCII |
| 5 会话层 | 应用层 | 建立/维护/终止会话 | 数据 | RPC, NetBIOS |
| 4 传输层 | 传输层 | 端到端可靠性、端口复用 | 段 Segment (TCP) / 数据报 Datagram (UDP) | TCP, UDP |
| 3 网络层 | 网际层 | 逻辑寻址、跨网转发 | 包 Packet | IP, ICMP, OSPF；**路由器** |
| 2 数据链路层 | 网络接口层 | 同一链路内寻址、成帧、纠错 | 帧 Frame | Ethernet, PPP, ARP；**交换机** |
| 1 物理层 | 网络接口层 | 比特流的电/光/无线信号 | 比特 Bit | 双绞线、光纤；**集线器** |

> **考点提示**：CCNP 考试里 OSI 分层本身考得少，但**排障题会隐含分层思想**——题目描述一个现象，问你"最可能的原因在哪一层"。所以分层的实际价值是排障框架，不是背诵素材。

### 2.3 封装：核心概念

数据从上往下走，每一层给它**加一个头**（有的还加尾）。这个过程叫**封装（Encapsulation）**；到了对端从下往上，每层**剥掉自己的头**，叫**解封装（De-encapsulation）**。

```
 应用层     ┌──────────────────────────────────────────┐
            │              HTTP 数据                    │
            └──────────────────────────────────────────┘
                              │ 交给 TCP
 传输层     ┌────────┬─────────────────────────────────┐
            │ TCP 头 │           HTTP 数据              │   ← 加了源/目的端口、序号、标志位
            └────────┴─────────────────────────────────┘
                              │ 交给 IP
 网络层     ┌───────┬────────┬─────────────────────────┐
            │ IP 头 │ TCP 头 │        HTTP 数据         │   ← 加了源/目的 IP、TTL、协议号
            └───────┴────────┴─────────────────────────┘
                              │ 交给以太网
 链路层  ┌──────┬───────┬────────┬──────────────┬─────┐
         │ 以太头│ IP 头 │ TCP 头 │   HTTP 数据   │ FCS │  ← 加了源/目的 MAC、类型；尾部校验
         └──────┴───────┴────────┴──────────────┴─────┘
                              │
 物理层            1010110100101110101...  比特流上线
```

**每一层关心的地址不一样**，这是最重要的一句话：

| 层 | 用什么地址 | 作用范围 | 转发过程中会变吗 |
|:--|:--|:--|:--|
| 传输层 | 端口号 | 主机内部的进程 | 一般不变（NAT 会改） |
| 网络层 | IP 地址 | 端到端，全程 | **不变**（NAT 会改） |
| 链路层 | MAC 地址 | 单跳，只在一条链路内有效 | **每一跳都变** |

### 2.4 一次完整的旅程（重点）

场景：`PC-A (192.168.1.10)` 访问 `Server (10.0.0.100)`，中间经过 `R1`、`R2`。

```
PC-A ──── SW ──── R1 ──────── R2 ──── Server
192.168.1.10          .1  .1      .2   10.0.0.100
                   192.168.1.0/24   172.16.0.0/30   10.0.0.0/24
```

**Step 1｜PC-A 判断目标是不是同网段**
用自己的子网掩码 `255.255.255.0` 分别 AND 自己的 IP 和目标 IP：
- `192.168.1.10 AND 255.255.255.0 = 192.168.1.0`
- `10.0.0.100 AND 255.255.255.0 = 10.0.0.0`
不相等 → **跨网段** → 把包交给默认网关 `192.168.1.1`。

**Step 2｜PC-A 需要网关的 MAC，发 ARP**
```
ARP Request（广播）
  目的 MAC: FF:FF:FF:FF:FF:FF
  内容: "谁是 192.168.1.1？告诉 192.168.1.10"
```
R1 回复 ARP Reply（单播），PC-A 学到 `192.168.1.1 → R1的MAC`。

> **关键**：PC-A 要的是**网关的 MAC**，不是服务器的 MAC。服务器在另一个广播域，ARP 广播到不了那儿。

**Step 3｜PC-A 封装并发出**

| 字段 | 值 |
|:--|:--|
| 源 MAC | PC-A 的 MAC |
| 目的 MAC | **R1 的 MAC** |
| 源 IP | 192.168.1.10 |
| 目的 IP | **10.0.0.100** |

**Step 4｜R1 处理**
1. 收到帧，检查目的 MAC 是自己 → 接收，**剥掉以太网头**
2. 查看 IP 头目的地址 `10.0.0.100`，查路由表 → 下一跳 `172.16.0.2`（R2）
3. **TTL 减 1**（比如 128 → 127），重算 IP 头校验和
4. ARP 得到 R2 的 MAC，**重新封装一个全新的以太网头**发出

| 字段 | 值 |
|:--|:--|
| 源 MAC | **R1 出接口的 MAC**（变了） |
| 目的 MAC | **R2 接口的 MAC**（变了） |
| 源 IP | 192.168.1.10（**没变**） |
| 目的 IP | 10.0.0.100（**没变**） |

**Step 5｜R2 处理**
同理，TTL 再减 1，查到 `10.0.0.0/24` 是直连，ARP 得到 Server 的 MAC，封装发出。此时目的 MAC 才终于是 Server 的 MAC。

**Step 6｜Server 收到**
逐层解封装：以太网头 → IP 头 → TCP 头 → 交给 80 端口监听的进程。

---

### 2.5 这一节要刻进肌肉记忆的三句话

1. **IP 地址端到端不变，MAC 地址逐跳改变。**
2. **交换机看 MAC 表转发（二层），路由器看路由表转发（三层）。**
3. **ARP 只在同一个广播域内有效**，跨网段永远先找网关。

## ③ 常用验证命令

### Cisco

```cisco
! 查看接口的 MAC / IP / 状态
Router# show interfaces GigabitEthernet0/0
Router# show ip interface brief

! 查看 ARP 表
Router# show arp
Router# show ip arp 192.168.1.10

! 查看 MAC 地址表（交换机）
Switch# show mac address-table
Switch# show mac address-table dynamic vlan 10

! 逐跳追踪（观察 TTL 递减）
Router# traceroute 10.0.0.100
```

## ④ 配套实验：亲眼看到封装

**目标**：用 Wireshark 抓包，验证"IP 不变、MAC 逐跳变"。

**拓扑**：
```
PC1 --- [R1] --- [R2] --- PC2
```

**步骤**：
1. 在 EVE-NG 里搭上述拓扑，配好 IP 和静态路由，确认 PC1 能 ping 通 PC2。
2. 在 **PC1–R1 链路**上抓包，PC1 执行 `ping <PC2的IP>`。
3. 展开一个 ICMP Request 包，记录：`Ethernet II` 的 Source/Destination，`Internet Protocol` 的 Source/Destination。
4. 在 **R1–R2 链路**上重复抓包，记录同样四个字段。

**预期结果**：

| 抓包位置 | 源 MAC | 目的 MAC | 源 IP | 目的 IP |
|:--|:--|:--|:--|:--|
| PC1–R1 | PC1 | R1-e0/0 | PC1 | PC2 |
| R1–R2 | R1-e0/1 | R2-e0/0 | **PC1（不变）** | **PC2（不变）** |

**同时观察**：IP 头里的 `Time to Live` 字段在第二段抓包中比第一段少 1。

## ⑤ 排障思路：分层定位法

遇到"访问不了"，按层从下往上排（或从上往下二分），**每一层都有一个明确的验证手段**：

| 层 | 症状 | 验证命令 | 常见根因 |
|:--|:--|:--|:--|
| L1 物理 | 接口 down/down | `show interfaces` 看 `line protocol` | 网线断、光模块坏、接口 shutdown |
| L2 链路 | 接口 up 但 ping 不通同网段 | `show mac address-table`、`show arp` | VLAN 不对、Trunk 未放行、ARP 学不到 |
| L3 网络 | 同网段通、跨网段不通 | `ping 网关`、`show ip route`、`traceroute` | 网关配错、路由缺失、ACL 拦截 |
| L4 传输 | ping 通但端口连不上 | `telnet <ip> <port>`、抓包看 RST | 服务没起、防火墙拦端口 |
| L7 应用 | 端口通但业务报错 | 看应用日志、抓包看返回码 | 配置错、证书过期、DNS 解析错 |

> **实战经验**：`ping 通但业务不通`，90% 是 L4 或 L7 的问题，别再纠结路由了。反过来 `ping 不通`，90% 在 L2/L3。

## ⑥ 考点提示 + 自测题

### 考点

- ENCOR 不直接考 OSI 定义，但**排障题会考"某现象属于哪一层"**。
- **封装/解封装的 MAC 变化**是理解 VXLAN、GRE、MPLS 的前提，必须扎实。
- TTL 递减机制是 `traceroute` 的原理，也是防环路的基础。

### 自测题

**1.** PC-A（192.168.1.10/24）ping PC-B（192.168.2.20/24），PC-A 发出的第一个以太网帧，目的 MAC 是什么？

<details><summary>答案</summary>

是**默认网关的 MAC**（如果 ARP 缓存里没有，会先发一个 ARP 广播 `FF:FF:FF:FF:FF:FF` 询问网关的 MAC）。

不可能是 PC-B 的 MAC —— PC-B 在另一个广播域，ARP 广播过不去，PC-A 也永远学不到它的 MAC。
</details>

**2.** 一个包经过 3 台路由器到达目的地，途中源 IP 地址变了几次？源 MAC 变了几次？（假设无 NAT）

<details><summary>答案</summary>

- 源 IP：**0 次**（端到端保持不变）
- 源 MAC：**3 次**（每台路由器转发时都会用自己出接口的 MAC 作为新的源 MAC）

如果有 NAT，源 IP 会在 NAT 设备上被改写一次。
</details>

**3.** 为什么交换机不会减少 TTL，而路由器会？

<details><summary>答案</summary>

TTL 在 **IP 头**里，属于三层字段。交换机是二层设备，**根本不解封装到 IP 层**，它只看以太网头的目的 MAC 就转发了，压根碰不到 TTL。

路由器必须解封装到三层才能查路由表，所以顺手把 TTL 减 1（这是 RFC 要求的防环机制）。

推论：**三层交换机做路由转发时也会减 TTL**，因为它此时行为等同路由器。
</details>

**4.** 用 `traceroute` 能看到路径上每一跳，它是怎么做到的？

<details><summary>答案</summary>

利用 TTL 递减。发送方先发 TTL=1 的包，第一跳路由器把 TTL 减到 0，丢弃并回一个 ICMP Time Exceeded（这样就暴露了第一跳的 IP）；再发 TTL=2，暴露第二跳……依次递增直到到达目的地。

**Cisco 设备的 traceroute 默认用 UDP**（端口 33434 起递增），Windows 的 `tracert` 用 ICMP。这个差异会导致同一条路径在不同工具下结果不同——因为防火墙对 UDP 和 ICMP 的策略可能不一样。这是个实战常见坑。
</details>
