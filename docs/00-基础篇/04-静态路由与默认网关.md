# 04 · 静态路由与默认网关

## ① 这章解决什么问题

两个办公室，深圳 `192.168.1.0/24`、上海 `192.168.2.0/24`，中间一条专线。怎么让两边互通？

答案是配路由。但更重要的问题是：**路由器收到一个包，它到底是怎么决定往哪儿送的？**

理解这个决策过程，你才能看懂后面 OSPF、EIGRP、BGP 学到的路由为什么有的进了路由表、有的没进；才能理解为什么"路由表里有路由但还是不通"。

---

## ② 原理讲透

### 2.1 路由表的结构

```cisco
R1# show ip route

Codes: L - local, C - connected, S - static, R - RIP, 
       O - OSPF, D - EIGRP, B - BGP, i - IS-IS
       * - candidate default

Gateway of last resort is 10.0.0.2 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 10.0.0.2
      10.0.0.0/8 is variably subnetted, 2 subnets, 2 masks
C        10.0.0.0/30 is directly connected, GigabitEthernet0/1
L        10.0.0.1/32 is directly connected, GigabitEthernet0/1
      192.168.1.0/24 is variably subnetted, 2 subnets, 2 masks
C        192.168.1.0/24 is directly connected, GigabitEthernet0/0
L        192.168.1.1/32 is directly connected, GigabitEthernet0/0
S     192.168.2.0/24 [1/0] via 10.0.0.2
O     192.168.3.0/24 [110/2] via 10.0.0.2, 00:05:12, GigabitEthernet0/1
```

拆解一条：
```
O     192.168.3.0/24 [110/2] via 10.0.0.2, 00:05:12, GigabitEthernet0/1
│           │          │  │        │          │              │
│           │          │  │        │          │              └─ 出接口
│           │          │  │        │          └─ 存在时长
│           │          │  │        └─ 下一跳 IP
│           │          │  └─ 度量值 Metric
│           │          └─ 管理距离 AD (Administrative Distance)
│           └─ 目的网络/掩码
└─ 来源：O = OSPF
```

**`C` 和 `L` 的区别**（很多人搞不清）：
- `C` (Connected)：接口所在的**整个网段**，用于转发去往该网段的流量
- `L` (Local)：接口自己的 **/32 主机地址**，用于识别"这个包是发给我自己的"

### 2.2 转发决策：最长匹配原则（Longest Prefix Match）

路由表里有三条：
```
S    10.0.0.0/8    via 1.1.1.1
S    10.1.0.0/16   via 2.2.2.2
S    10.1.1.0/24   via 3.3.3.3
```

去往 `10.1.1.5` 的包走哪条？

**走 `10.1.1.0/24` → 3.3.3.3**。因为三条都匹配，但 `/24` 的掩码最长（最具体）。

> **核心规则**：**最长匹配优先，与管理距离、度量值无关**。AD 和 Metric 只在**同一前缀长度**的多条路由之间才用来比较。

这个优先级顺序必须刻在脑子里：

```
1. 最长匹配（前缀长度）      ← 第一优先，一票否决
       ↓ 同样长
2. 管理距离 AD（谁更可信）    ← 决定哪个协议的路由进表
       ↓ 同协议
3. 度量值 Metric（谁更近）    ← 同协议内选最优
       ↓ 度量值也相同
4. 等价负载均衡 ECMP
```

### 2.3 管理距离 AD

当同一个网段被多个来源学到时，路由器信谁？靠 AD，**数字越小越可信**。

| 来源 | AD | 记忆 |
|:--|:--|:--|
| 直连 Connected | **0** | 亲眼所见，最可信 |
| 静态路由 Static | **1** | 管理员手写，很可信 |
| EIGRP 汇总路由 | 5 | |
| eBGP | **20** | 外部 BGP |
| EIGRP（内部） | **90** | |
| OSPF | **110** | |
| IS-IS | 115 | |
| RIP | **120** | |
| EIGRP（外部） | 170 | 重分发进来的 |
| iBGP | **200** | 内部 BGP，不如 IGP 可信 |
| 未知/不可达 | **255** | AD=255 的路由**永远不会进路由表** |

**必背**：`0 / 1 / 20 / 90 / 110 / 120 / 200`。这七个数在 ENCOR、ENARSI 里反复出现。

> **eBGP(20) < OSPF(110)** 这一点很反直觉但很关键：外部 BGP 学到的路由比内部 OSPF 更"可信"。在同时跑 BGP 和 OSPF 的边界路由器上，这会导致 BGP 路由覆盖 IGP 路由——ENARSI 有专门的题考这个陷阱。

### 2.4 静态路由的三种写法

```cisco
! 写法 1：指定下一跳 IP（推荐，最通用）
R1(config)# ip route 192.168.2.0 255.255.255.0 10.0.0.2

! 写法 2：指定出接口（仅推荐用于点对点链路）
R1(config)# ip route 192.168.2.0 255.255.255.0 Serial0/0

! 写法 3：两者都写（最明确，多路访问网络的最佳实践）
R1(config)# ip route 192.168.2.0 255.255.255.0 GigabitEthernet0/1 10.0.0.2
```

**为什么以太网上不能只写出接口？**

写法 2 在以太网（多路访问网络）上会让路由器认为"目标网段是直连的"，于是对**每一个目的 IP 都发 ARP**。这叫 **Proxy ARP 依赖**：
- 如果对端路由器开了 Proxy ARP，能通，但路由器的 ARP 表会膨胀到爆炸
- 如果对端关了 Proxy ARP（现代设备多数默认关闭），**直接不通**

**串行链路（PPP/HDLC）可以只写出接口**，因为点对点链路上"从这个口出去"没有歧义，不需要 ARP。

### 2.5 默认路由

```cisco
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.2
```

`0.0.0.0/0` 匹配任意地址，但因为掩码长度是 0（最短），所以它是**最后的选择**——只有没有任何更具体的路由匹配时才用它。这就是 `show ip route` 里说的 **Gateway of last resort**。

**典型用法**：分支机构只需一条默认路由指向总部/出口，不需要知道全网明细。

### 2.6 浮动静态路由（Floating Static Route）

主备链路场景：主用走专线，专线断了自动切到 4G/宽带备份。

```cisco
! 主路由，默认 AD = 1
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.2

! 备份路由，手工把 AD 调大到 10
R1(config)# ip route 0.0.0.0 0.0.0.0 172.16.0.2 10
                                                 ↑ 这个数字就是 AD
```

**工作原理**：AD=1 的更可信，所以平时只有它在路由表里；一旦它的**出接口 down**（或下一跳不可达），它从路由表消失，AD=10 的那条自动顶上。

**⚠️ 致命陷阱**：如果链路是通过交换机/光猫中转，**物理接口不会 down**（本地口还是 up 的），故障发生在远端，浮动路由**不会切换**。

**解法：IP SLA + Track**（ENCOR 必考）
```cisco
! 定义探测：每 5 秒 ping 一次 8.8.8.8
R1(config)# ip sla 1
R1(config-ip-sla)#  icmp-echo 8.8.8.8 source-interface GigabitEthernet0/1
R1(config-ip-sla)#  frequency 5
R1(config)# ip sla schedule 1 life forever start-time now

! 把探测结果绑到一个 track 对象
R1(config)# track 1 ip sla 1 reachability

! 主路由挂钩 track：探测失败则撤销该路由
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.2 track 1
R1(config)# ip route 0.0.0.0 0.0.0.0 172.16.0.2 10

! 验证
R1# show ip sla statistics
R1# show track
```

这样即使本地接口一直 up，只要探测不通，主路由也会被撤下，实现真正的故障切换。详见 [ENCOR 第 12 章](../02-ENCOR-350-401/12-IP服务-NTP-NAT-SLA-NetFlow-SNMP-Syslog.md)。

### 2.7 特殊静态路由

```cisco
! 主机路由（/32），只匹配一个 IP
R1(config)# ip route 8.8.8.8 255.255.255.255 10.0.0.2

! 黑洞路由（丢弃流量），常用于防环和抑制无效流量
R1(config)# ip route 192.168.99.0 255.255.255.0 Null0

! 递归路由：下一跳不是直连的，路由器要再查一次表找到怎么去 20.0.0.2
R1(config)# ip route 192.168.5.0 255.255.255.0 20.0.0.2
```

**Null0 黑洞路由的实战用途**：
1. **防止路由环路**：做汇总时，给汇总网段配一条指向 Null0 的路由，落在汇总范围内但没有明细的流量直接丢弃，不会在设备间来回弹（BGP 通告聚合路由时的标准做法）
2. **应急阻断攻击源**：`ip route <攻击源> 255.255.255.255 Null0`，比 ACL 更省 CPU（走硬件转发路径）

## ③ 配置命令

### Cisco

```cisco
! ── 静态路由 ──
Router(config)# ip route <目的网络> <掩码> <下一跳|出接口> [AD] [name 描述]
Router(config)# ip route 192.168.2.0 255.255.255.0 10.0.0.2 name TO-SHANGHAI
Router(config)# no ip route 192.168.2.0 255.255.255.0 10.0.0.2   ! 删除

! ── 默认路由 ──
Router(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.2

! ── IPv6 静态路由 ──
Router(config)# ipv6 unicast-routing
Router(config)# ipv6 route 2001:db8:2::/64 2001:db8:12::2
Router(config)# ipv6 route ::/0 2001:db8:12::2

! ── 查看 ──
Router# show ip route
Router# show ip route static
Router# show ip route 192.168.2.100        ! 关键：看某IP实际匹配哪条
Router# show ip route | include 192.168
Router# show ip cef 192.168.2.100          ! 看硬件转发表（CEF）实际怎么走

! ── 验证连通性 ──
Router# ping 192.168.2.1
Router# ping 192.168.2.1 source GigabitEthernet0/0    ! 指定源，很重要
Router# traceroute 192.168.2.1
Router# ping                                          ! 扩展 ping，可设大小/次数/DF位
```

**扩展 ping 用法**（排 MTU 问题必备）：
```cisco
R1# ping
Protocol [ip]:
Target IP address: 192.168.2.1
Repeat count [5]: 100
Datagram size [100]: 1500
Timeout in seconds [2]:
Extended commands [n]: y
Source address or interface: GigabitEthernet0/0
...
Set DF bit in IP header? [no]: yes      ← 关键：不允许分片
```
如果 1500 字节 + DF 位不通，但小包能通，**基本可断定路径上有 MTU 瓶颈**（GRE/IPsec/MPLS 隧道最常见）。

### 三厂商对照

| 目的 | Cisco | H3C | 华为 |
|:--|:--|:--|:--|
| 静态路由 | `ip route 192.168.2.0 255.255.255.0 10.0.0.2` | `ip route-static 192.168.2.0 24 10.0.0.2` | `ip route-static 192.168.2.0 24 10.0.0.2` |
| 默认路由 | `ip route 0.0.0.0 0.0.0.0 10.0.0.2` | `ip route-static 0.0.0.0 0 10.0.0.2` | `ip route-static 0.0.0.0 0 10.0.0.2` |
| 带优先级 | `ip route ... 10.0.0.2 200` | `ip route-static ... 10.0.0.2 preference 200` | `ip route-static ... 10.0.0.2 preference 200` |
| 黑洞路由 | `ip route ... Null0` | `ip route-static ... NULL 0` | `ip route-static ... NULL 0` |
| 查路由表 | `show ip route` | `display ip routing-table` | `display ip routing-table` |
| 查特定路由 | `show ip route 1.1.1.1` | `display ip routing-table 1.1.1.1` | `display ip routing-table 1.1.1.1` |

> **术语差异**：Cisco 叫 **Administrative Distance (AD)**，H3C/华为叫 **优先级 Preference**。数值含义相同（越小越优），但**默认值不同**！例如 H3C 静态路由默认 preference=60，OSPF=10；而 Cisco 静态=1，OSPF=110。混合组网时这是个大坑。

## ④ 配套实验：三路由器静态路由 + 浮动备份

**拓扑**：
```
                    10.0.12.0/30
     ┌─────┐  .1 ═════════════ .2  ┌─────┐
LAN1─┤ R1  │                       │ R2  ├─LAN2
     └──┬──┘                       └──┬──┘  192.168.2.0/24
192.168.1.0/24                        │
        │        10.0.13.0/30         │  10.0.23.0/30
        └──────── .1 ┌─────┐ .3 ──────┘
                     │ R3  │
                     └─────┘
```

R1—R2 是主链路，R1—R3—R2 是备份路径。

**Step 1：基础配置（R1 为例）**
```cisco
R1(config)# interface Gi0/0
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# no shutdown
R1(config)# interface Gi0/1
R1(config-if)# ip address 10.0.12.1 255.255.255.252
R1(config-if)# no shutdown
R1(config)# interface Gi0/2
R1(config-if)# ip address 10.0.13.1 255.255.255.252
R1(config-if)# no shutdown
```

**Step 2：配主备静态路由**
```cisco
! R1: 去 LAN2 主走 R2，备走 R3
R1(config)# ip route 192.168.2.0 255.255.255.0 10.0.12.2
R1(config)# ip route 192.168.2.0 255.255.255.0 10.0.13.3 10

! R2: 回程也要配！(否则单向通)
R2(config)# ip route 192.168.1.0 255.255.255.0 10.0.12.1
R2(config)# ip route 192.168.1.0 255.255.255.0 10.0.23.3 10

! R3: 转发两边
R3(config)# ip route 192.168.1.0 255.255.255.0 10.0.13.1
R3(config)# ip route 192.168.2.0 255.255.255.0 10.0.23.2
```

**Step 3：验证主路径**
```cisco
R1# show ip route 192.168.2.0
Routing entry for 192.168.2.0/24
  Known via "static", distance 1, metric 0
  Routing Descriptor Blocks:
  * 10.0.12.2
```
✓ 只有主路由在表里，AD=1。

```cisco
R1# traceroute 192.168.2.1 source Gi0/0
  1  10.0.12.2  4 msec  ...      ← 直接到 R2，只有 1 跳
```

**Step 4：模拟主链路故障**
```cisco
R1(config)# interface Gi0/1
R1(config-if)# shutdown
```

**Step 5：验证切换**
```cisco
R1# show ip route 192.168.2.0
Routing entry for 192.168.2.0/24
  Known via "static", distance 10, metric 0    ← AD 变成 10
  Routing Descriptor Blocks:
  * 10.0.13.3

R1# traceroute 192.168.2.1 source Gi0/0
  1  10.0.13.3  4 msec              ← 经过 R3
  2  10.0.23.2  8 msec              ← 到 R2
```
✓ 自动切到备份路径。

**Step 6：恢复**
```cisco
R1(config-if)# no shutdown
```
路由自动切回主路径。

**进阶挑战**：把主链路中间插一台交换机，再次 `shutdown` **交换机上连 R2 的那个口**（而不是 R1 的口）。观察 R1 的路由是否切换。

**预期**：**不会切换**！因为 R1 的 Gi0/1 依然 up。这时候你就需要 IP SLA + Track 了——请自行实现并验证。

## ⑤ 排障思路

### 症状 → 怀疑点 → 验证 → 根因

| 症状 | 验证命令 | 常见根因 |
|:--|:--|:--|
| 路由表里没有该网段 | `show ip route <网段>` | 静态路由没配 / 写错掩码 / 出接口 down |
| **A 能 ping B，B 不能 ping A** | 在 B 上 `show ip route <A的网段>` | **回程路由缺失**（占单向不通故障的 80%） |
| 路由表里有路由但不通 | `traceroute`、逐跳 `show ip route` | 中间某跳缺路由 / ACL 拦截 / 下一跳不可达 |
| 路由存在但流量走错路 | `show ip route <具体目的IP>` | 有更具体的路由抢走了（最长匹配） |
| 配了浮动路由但不切换 | `show ip interface brief` | 本地接口没 down，需要 IP SLA + Track |
| 大包不通小包通 | `ping ... size 1500 df-bit` | **MTU 问题**，路径上有隧道/封装 |
| 路由表里有但 `show ip cef` 没有 | `show ip cef <目的>` | CEF 与 RIB 不同步（罕见，需 `clear ip route *`） |

### 万能三板斧

排任何"不通"的问题，先按这个顺序：

```
第 1 步：源端有没有去程路由？
        R_source# show ip route <目的IP>
        
第 2 步：目的端有没有回程路由？          ← 最容易被忽略
        R_dest# show ip route <源IP>
        
第 3 步：中间每一跳都有吗？
        R# traceroute <目的IP> source <源接口>
        看在哪一跳开始出现 * * *
```

> **实战心法**：`traceroute` 一定要加 `source`。不加的话路由器会用**出接口地址**作为源，而这个地址可能在对端根本没有回程路由，导致你看到"不通"的假象，白白排查半天。

### 单向不通的完整排查

```cisco
! 在 R1（源）上确认去程
R1# show ip route 192.168.2.0
! 有路由 ✓

! 在 R2（目的）上确认回程 —— 关键步骤
R2# show ip route 192.168.1.0
% Network not in table                     ← 找到问题！

! 补上回程路由
R2(config)# ip route 192.168.1.0 255.255.255.0 10.0.12.1
```

**为什么这么常见？** 因为人配路由时容易只想着"我要去哪儿"，忘了"对方怎么回来"。**路由是双向的，永远成对配置。**

## ⑥ 考点提示 + 自测题

### 考点

- **AD 值表必背**，尤其 0/1/20/90/110/120/200。
- **最长匹配优先于 AD** —— 这是最爱考的陷阱。
- **浮动静态路由 + IP SLA/Track** 在 ENCOR 和 ENARSI 都是重点。
- **Null0 黑洞路由防环**在 BGP 聚合、EIGRP/OSPF 汇总中都会出现。
- 静态路由**只写出接口在以太网上的问题**是经典理解题。

### 自测题

**1.** 路由表里同时存在这四条，去往 `172.16.5.100` 的包走哪条？
```
S    172.16.0.0/16     [1/0]   via 10.0.0.1
O    172.16.4.0/22     [110/2] via 10.0.0.2
D    172.16.5.0/24     [90/1]  via 10.0.0.3
B    172.16.5.100/32   [20/0]  via 10.0.0.4
```

<details><summary>答案</summary>

**走 `172.16.5.100/32` → 10.0.0.4**。

最长匹配优先。`/32` 最具体，胜过所有其他路由，**跟 AD 完全无关**——即使 BGP 的 AD(20) 比静态(1) 大得多。

这道题专门考"最长匹配 > AD"这个优先级。很多人会被 AD=1 的静态路由误导。
</details>

**2.** 同一个网段 `10.1.1.0/24` 同时被 OSPF 和 EIGRP 学到，路由表里会是哪条？如果想让 OSPF 那条生效怎么办？

<details><summary>答案</summary>

**EIGRP 的会进表**，因为 EIGRP 内部路由 AD=90 < OSPF AD=110。

**让 OSPF 生效的两种办法**：

```cisco
! 方法 1：调低 OSPF 的 AD（全局或针对特定路由）
R1(config)# router ospf 1
R1(config-router)# distance 80

! 或只针对特定前缀（更精细）
R1(config)# access-list 10 permit 10.1.1.0 0.0.0.255
R1(config-router)# distance 80 0.0.0.0 255.255.255.255 10

! 方法 2：调高 EIGRP 的 AD
R1(config)# router eigrp 100
R1(config-router)# distance eigrp 150 170
                                  ↑内部  ↑外部
```

**实战警告**：改 AD 是"局部行为"，只影响这一台设备。如果只在一台上改，很容易造成**路由不对称**甚至环路。改之前务必想清楚全网影响面。
</details>

**3.** 为什么在以太网接口上配 `ip route 192.168.2.0 255.255.255.0 GigabitEthernet0/1`（只写出接口）是不推荐的？

<details><summary>答案</summary>

以太网是**多路访问网络**（一个网段可以挂多台设备）。只写出接口，路由器会认为 `192.168.2.0/24` 是**直连**的，于是对该网段内**每一个目的 IP 都发 ARP 请求**。

后果：
1. 依赖对端路由器开启 **Proxy ARP** 才能通。现代设备（尤其是 IOS-XE 15.x 之后的某些平台和多数三层交换机）默认可能关闭 Proxy ARP，直接不通。
2. 即使能通，路由器的 **ARP 表会为目标网段的每个 IP 生成一条表项**，大网段下会耗尽 ARP 资源，影响性能。
3. 收敛慢：ARP 超时（默认 4 小时）导致故障恢复不及时。

**正确写法**：`ip route 192.168.2.0 255.255.255.0 GigabitEthernet0/1 10.0.0.2`（出接口 + 下一跳都写），既明确又不依赖 Proxy ARP。

**例外**：真正的点对点链路（Serial 接口跑 PPP/HDLC、Tunnel 接口）可以只写出接口，因为没有寻址歧义。
</details>

**4.** 配了浮动静态路由做备份，主链路的对端设备断电了，但路由没有切换到备份。为什么？怎么解决？

<details><summary>答案</summary>

**原因**：主路由的撤销条件是**本地出接口 down 或下一跳不可达**。如果 R1 和 R2 之间经过交换机、光猫、运营商设备中转，对端断电后 **R1 的本地接口依然 up**（它连的是交换机，链路层没断），所以主路由不会从路由表消失，流量继续往黑洞里送。

**解决方案：IP SLA + Track**

```cisco
! 1. 探测对端（或更远的可靠目标）
R1(config)# ip sla 1
R1(config-ip-sla)#  icmp-echo 10.0.12.2 source-interface Gi0/1
R1(config-ip-sla)#  frequency 5
R1(config-ip-sla)#  threshold 1000
R1(config-ip-sla)#  timeout 2000
R1(config)# ip sla schedule 1 life forever start-time now

! 2. 绑定 track 对象
R1(config)# track 1 ip sla 1 reachability
R1(config-track)#  delay down 10 up 30      ! 防抖：down 确认10秒，up 确认30秒

! 3. 主路由挂钩 track
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.12.2 track 1
R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.13.3 10

! 验证
R1# show track 1
R1# show ip sla statistics 1
```

**探测目标选择建议**：
- 探测**直连对端接口**：只能发现该链路故障
- 探测**更远的公网地址**（如 8.8.8.8 或运营商网关）：能发现整条路径故障，但要注意目标本身可能不稳定，建议探测两个目标做 `track list`

**`delay down/up` 参数很重要**：不加防抖的话，链路轻微抖动就会引发路由频繁切换（路由震荡），比不切换更糟。
</details>

**5.** `ping 192.168.2.1` 不通，但 `ping 192.168.2.1 source GigabitEthernet0/0` 通。这说明什么？

<details><summary>答案</summary>

说明**对端有去往 Gi0/0 网段的回程路由，但没有去往默认源接口（出接口）网段的回程路由**。

不加 `source` 时，路由器用**出接口的 IP** 作为源地址。比如 R1 从 Gi0/1（10.0.12.1）出去，源 IP 就是 10.0.12.1。如果对端 R2 没有回 `10.0.12.0/30` 的路由（或者中间设备没有），ICMP Reply 就回不来。

加了 `source Gi0/0` 后，源 IP 变成 192.168.1.1，而对端恰好有 `192.168.1.0/24` 的回程路由，所以通。

**实战教训**：**排障时永远显式指定 source**，模拟真实业务流量的源地址。否则你测出来的结果跟用户实际体验对不上，会把你带进沟里。

这也是为什么很多人抱怨"路由器上 ping 不通但用户能上网"或者反过来——测试的源地址跟业务的源地址不是一回事。
</details>
