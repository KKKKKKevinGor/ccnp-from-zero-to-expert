# 03 · IP 编址与子网划分

> ⚠️ **这是整个基础篇最重要的一章。** 请花掉基础篇一半的时间在这里。
> 通过标准：**不用计算器，30 秒内**算出任意 CIDR 的网络地址、广播地址、可用主机范围、主机数。

## ① 这章解决什么问题

公司分到一个 `172.16.0.0/16`，需要给 12 个部门各分一个独立网段，每个部门规模从 20 人到 500 人不等，另外还有 30 条设备互联的点对点链路。怎么切？

这就是子网划分。它不只是考试题——它是你作为网络工程师最基础的日常工作。而且更重要的是：

- **ACL 的通配符掩码** 是子网掩码的反码
- **路由汇总** 就是反向做子网划分
- **OSPF 区域规划** 依赖于地址能否汇总
- **BGP 的前缀过滤** 用的是 prefix-list 的 `ge`/`le`

**这些全部建立在你能把 IP 当成 32 位二进制来玩。**

## ② 原理讲透

### 2.1 IPv4 地址结构

32 位，分 4 个字节（八位组 Octet），点分十进制表示：

```
   192   .   168   .    1    .   10
 11000000 10101000 00000001 00001010
 └──────────────────────────────────┘
              32 bits
```

**必须背下来的 8 个数**（一个字节内每一位的权重）：

```
 位:    1    2    3    4    5    6    7    8
 权重: 128   64   32   16    8    4    2    1
```

### 2.2 子网掩码

掩码用连续的 1 标记**网络位**，连续的 0 标记**主机位**。

```
 IP:    192.168.1.10   = 11000000.10101000.00000001.00001010
 Mask:  255.255.255.0  = 11111111.11111111.11111111.00000000
                         └──────── 网络位 ───────┘└─主机位─┘
 
 网络地址 = IP AND Mask = 192.168.1.0
 广播地址 = 网络地址，主机位全置 1 = 192.168.1.255
```

**CIDR 记法** `/24` 就是"掩码里有 24 个 1"。

**必须背熟的掩码对照表**：

| CIDR | 点分十进制掩码 | 块大小 | 总地址数 | 可用主机数 | 常见用途 |
|:--|:--|:--|:--|:--|:--|
| /8  | 255.0.0.0       | 16777216 | 16777216 | 16777214 | A 类 |
| /16 | 255.255.0.0     | 65536 | 65536 | 65534 | B 类 |
| /24 | 255.255.255.0   | 256 | 256 | 254 | 标准 LAN |
| /25 | 255.255.255.128 | 128 | 128 | 126 | |
| /26 | 255.255.255.192 | 64 | 64 | 62 | 小部门 |
| /27 | 255.255.255.224 | 32 | 32 | 30 | 小网段 |
| /28 | 255.255.255.240 | 16 | 16 | 14 | 服务器组 |
| /29 | 255.255.255.248 | 8 | 8 | 6 | 极小网段 |
| /30 | 255.255.255.252 | 4 | 4 | **2** | **点对点链路** |
| /31 | 255.255.255.254 | 2 | 2 | **2**（RFC3021） | 点对点，省地址 |
| /32 | 255.255.255.255 | 1 | 1 | 1 | 环回口 / 主机路由 |

可用主机数 = `2^(主机位数) - 2`（减掉网络地址和广播地址）。
**例外**：`/31` 按 RFC 3021 在点对点链路上两个地址都可用；`/32` 用于 Loopback 和主机路由。

### 2.3 秒算法（核心技能）

**不要做二进制换算。用"块大小"法。**

#### 步骤

1. 看掩码，找出**不是 255 也不是 0 的那个字节**，称为"关键字节"
2. **块大小 = 256 − 关键字节的值**
3. 从 0 开始，以块大小为步长列出该字节的所有边界
4. 目标 IP 落在哪两个边界之间，前一个边界就是网络地址

#### 例题 1：`192.168.1.100/26`

```
/26 → 255.255.255.192
关键字节 = 第 4 个字节，值 192
块大小 = 256 − 192 = 64
边界: 0, 64, 128, 192
100 落在 64 和 128 之间 → 网络地址 = 192.168.1.64
```

| 项目 | 值 |
|:--|:--|
| 网络地址 | 192.168.1.**64** |
| 广播地址 | 192.168.1.**127**（下一个边界 128 减 1） |
| 可用范围 | 192.168.1.**65 ~ 126** |
| 可用主机数 | 62 |

#### 例题 2：`172.16.30.0/22`（本章必会题）

```
/22 → 255.255.252.0
关键字节 = 第 3 个字节，值 252
块大小 = 256 − 252 = 4
边界: 0, 4, 8, 12, 16, 20, 24, 28, 32, ...
30 落在 28 和 32 之间 → 网络地址 = 172.16.28.0
```

| 项目 | 值 |
|:--|:--|
| 网络地址 | 172.16.**28**.0 |
| 广播地址 | 172.16.**31.255**（下一网络 172.16.32.0 减 1） |
| 可用范围 | 172.16.**28.1 ~ 172.16.31.254** |
| 可用主机数 | 2^10 − 2 = **1022** |

> 注意这里网络地址不是 `172.16.30.0`！这是最常见的错误。`/22` 的边界是 4 的倍数，30 不是 4 的倍数，所以它在 28 这个块里。

#### 例题 3：`10.5.77.200/29`

```
/29 → 255.255.255.248
块大小 = 256 − 248 = 8
边界: 0, 8, 16, ..., 192, 200, 208, ...
200 正好是边界 → 网络地址 = 10.5.77.200
```

| 项目 | 值 |
|:--|:--|
| 网络地址 | 10.5.77.**200** |
| 广播地址 | 10.5.77.**207** |
| 可用范围 | 10.5.77.**201 ~ 206** |
| 可用主机数 | 6 |

### 2.4 VLSM：变长子网掩码

回到开头的问题：12 个部门，规模不一，还有 30 条 P2P 链路。如果每个都给 `/24`，一个大部门 500 人不够用，一个小部门 20 人浪费 234 个地址，P2P 链路更是浪费 252 个。

**VLSM 的原则：按需分配，从大到小。**

#### 实战案例：`172.16.0.0/16` 规划

需求：
- 研发部 500 人
- 销售部 200 人
- 财务部 20 人
- 30 条设备互联 P2P 链路

**第一步：按需求排序（大 → 小），算出每个需要的掩码**

| 部门 | 需求主机数 | 需要主机位 | 掩码 | 实际可用 |
|:--|:--|:--|:--|:--|
| 研发 | 500 | 2^9−2=510 ≥ 500 → 9 位 | **/23** | 510 |
| 销售 | 200 | 2^8−2=254 ≥ 200 → 8 位 | **/24** | 254 |
| 财务 | 20 | 2^5−2=30 ≥ 20 → 5 位 | **/27** | 30 |
| P2P ×30 | 2 | 2 位 | **/30** | 2 |

> 关键：先满足**大的**，因为大块必须对齐到大的边界。反过来先分小的会造成碎片。

**第二步：从头开始切**

```
172.16.0.0/16
│
├─ 172.16.0.0/23      研发部    (172.16.0.1   ~ 172.16.1.254)   块大小 2
│
├─ 172.16.2.0/24      销售部    (172.16.2.1   ~ 172.16.2.254)   块大小 1
│
├─ 172.16.3.0/27      财务部    (172.16.3.1   ~ 172.16.3.30)    块大小 32
├─ 172.16.3.32/27     预留
├─ 172.16.3.64/27     预留
│  ...
│
└─ 172.16.100.0/24 划出来专门做 P2P，再切成 /30：
   ├─ 172.16.100.0/30    链路1  (.1 ~ .2)
   ├─ 172.16.100.4/30    链路2  (.5 ~ .6)
   ├─ 172.16.100.8/30    链路3  (.9 ~ .10)
   ├─ 172.16.100.12/30   链路4  (.13 ~ .14)
   │  ...  一个 /24 可切出 64 条 /30，够 30 条链路
```

> **实战最佳实践**：把 P2P 链路地址**集中在一个连续块**里（比如都从 `172.16.100.0/24` 出），这样后面做路由汇总时可以一条 `172.16.100.0/24` 覆盖全部互联地址，OSPF/BGP 的通告表会非常干净。这个习惯会在你规划大网时救你的命。

### 2.5 路由汇总（子网划分的逆运算）

把多条明细路由合并成一条。ENCOR/ENARSI 高频考点。

#### 方法：找公共前缀

汇总这四条：
```
192.168.4.0/24
192.168.5.0/24
192.168.6.0/24
192.168.7.0/24
```

只看第 3 个字节的二进制：
```
 4 = 00000100
 5 = 00000101
 6 = 00000110
 7 = 00000111
     └────┬─┘└┬┘
     相同6位  不同
```
前两个字节全相同（16 位）+ 第三字节前 6 位相同 = **22 位**

**汇总结果：`192.168.4.0/22`**

验证：`/22` 块大小 = 4，边界 0,4,8... → `192.168.4.0/22` 覆盖 4,5,6,7。✓

#### 反例（不能汇总的情况）

```
192.168.5.0/24
192.168.6.0/24
192.168.7.0/24
```
如果强行算，需要 `192.168.4.0/22`——但这**多包含了 192.168.4.0/24**，是一条"过度汇总"。

**后果**：如果 `192.168.4.0/24` 实际存在于别处，流量会被错误地吸引过来，形成黑洞。ENARSI 排障题很爱考这个。

**规则**：可汇总的地址块必须是**连续的**，且数量是 **2 的幂**，且起始地址在对应块大小的**边界上**。

### 2.6 特殊地址速查

| 地址范围 | 名称 | 说明 |
|:--|:--|:--|
| `10.0.0.0/8` | 私有 A | RFC 1918 |
| `172.16.0.0/12` | 私有 B | RFC 1918，即 172.16.x ~ 172.31.x |
| `192.168.0.0/16` | 私有 C | RFC 1918 |
| `127.0.0.0/8` | 环回 | localhost |
| `169.254.0.0/16` | APIPA / 链路本地 | **DHCP 失败时自动生成** —— 看到这个地址第一反应就是"DHCP 没拿到" |
| `224.0.0.0/4` | 组播 | 224.0.0.5=OSPF全部路由器, 224.0.0.10=EIGRP |
| `100.64.0.0/10` | 运营商级 NAT (CGNAT) | RFC 6598 |
| `0.0.0.0/0` | 默认路由 | "任意地址" |
| `255.255.255.255` | 受限广播 | 不被路由器转发 |

> **实战**：用户报"上不了网"，你远程一看 IP 是 `169.254.x.x` —— 直接跳过所有网络排查，去查 DHCP 服务器 / DHCP 中继 / 端口 VLAN。这条经验能省你半小时。

### 2.7 通配符掩码（Wildcard Mask）

ACL、OSPF network 语句、路由策略都用它。

**通配符掩码 = 255.255.255.255 − 子网掩码**（即掩码取反）

| 子网掩码 | 通配符掩码 | 含义 |
|:--|:--|:--|
| 255.255.255.0 (/24) | 0.0.0.255 | 匹配整个 /24 |
| 255.255.255.192 (/26) | 0.0.0.63 | 匹配 /26 |
| 255.255.255.255 (/32) | 0.0.0.0 | 精确匹配一个主机（可写 `host x.x.x.x`） |
| 0.0.0.0 (/0) | 255.255.255.255 | 匹配任意（可写 `any`） |

**记忆**：通配符里 **0 = 必须匹配**，**1 = 不关心**。跟子网掩码正好相反。

**非连续通配符**（进阶，考试偶尔出现）：
```
access-list 10 permit 192.168.0.0 0.0.255.1
```
`0.0.255.1` 的最后一位是 1（不关心），倒数第二位起是 0 —— 这会匹配第 4 字节为**奇数或偶数**的特定模式。实战极少用，但要能看懂。

常用技巧：匹配所有偶数第三字节的网段 `10.0.0.0 0.0.254.255`。

### 第二组：VLSM 规划

给你 `192.168.10.0/24`，规划如下需求，要求**不浪费**、地址连续：

- 网段 A：50 台主机
- 网段 B：25 台主机
- 网段 C：12 台主机
- 3 条 P2P 链路

<details><summary>答案</summary>

从大到小分配：

| 用途 | 需求 | 掩码 | 网段 | 可用范围 | 可用数 |
|:--|:--|:--|:--|:--|:--|
| A | 50 | /26 (62个) | 192.168.10.0/26 | .1 ~ .62 | 62 |
| B | 25 | /27 (30个) | 192.168.10.64/27 | .65 ~ .94 | 30 |
| C | 12 | /28 (14个) | 192.168.10.96/28 | .97 ~ .110 | 14 |
| P2P 1 | 2 | /30 | 192.168.10.112/30 | .113 ~ .114 | 2 |
| P2P 2 | 2 | /30 | 192.168.10.116/30 | .117 ~ .118 | 2 |
| P2P 3 | 2 | /30 | 192.168.10.120/30 | .121 ~ .122 | 2 |
| 剩余 | | | 192.168.10.124 ~ .255 | 未分配，可扩展 | |

**为什么必须从大到小？** 如果先分 C（/28，从 0 开始占 0~15），再分 A（/26），A 只能从 64 开始（因为 /26 的边界必须是 64 的倍数，16/32/48 都不是合法的 /26 起始），16~63 这 48 个地址就成了碎片，只能拿来做小网段。从大到小分配能保证零碎片。
</details>

### 第三组：路由汇总

汇总下列路由，写出最精确（不多包含额外网段）的汇总路由：

1. `10.1.0.0/24, 10.1.1.0/24, 10.1.2.0/24, 10.1.3.0/24`
2. `172.16.16.0/24 ~ 172.16.23.0/24`（共 8 条）
3. `192.168.8.0/24, 192.168.9.0/24, 192.168.10.0/24`（只有 3 条）

<details><summary>答案</summary>

**1.** `10.1.0.0/22`
（4 条 /24 = 2^2，掩码减 2 位：24−2=22。起始 10.1.0.0 在 /22 边界上 ✓）

**2.** `172.16.16.0/21`
（8 条 = 2^3，24−3=21。/21 块大小 8，16 是 8 的倍数 ✓，覆盖 16~23 ✓）

**3.** **无法精确汇总。** 3 不是 2 的幂。
- 如果用 `192.168.8.0/22`，会额外包含 `192.168.11.0/24`（过度汇总，可能造成黑洞）
- 精确做法是拆成两条：`192.168.8.0/23`（覆盖 8、9）+ `192.168.10.0/24`

**实战判断**：如果 `192.168.11.0/24` 在本网络中确实不存在于别处，用 `/22` 汇总是可以接受的，能简化路由表。但如果它属于其他区域/其他 AS，就绝不能这么汇总。
</details>

## ⑤ 排障思路

| 症状 | 怀疑点 | 验证 | 根因 |
|:--|:--|:--|:--|
| 主机 IP 是 `169.254.x.x` | DHCP | `show ip dhcp binding`、检查中继 | DHCP 服务未响应 / VLAN 错 / 中继未配 |
| 同网段能通，网关不通 | 掩码或网关配置 | 核对主机与网关的掩码是否一致 | **掩码不一致**导致双方对"是否同网段"判断不同 |
| A 能 ping B，B ping 不通 A | 单向路由 | 两端 `show ip route` | 回程路由缺失（**最经典的单向不通原因**） |
| 部分主机通、部分不通 | 子网边界算错 | 核对每台主机是否在正确子网内 | 有主机 IP 落在了相邻子网 |
| 配 IP 报 "Bad mask" | 地址是网络/广播地址 | 重新计算 | 试图把网络地址或广播地址配到接口上 |
| 汇总后某网段不可达 | 过度汇总 | `show ip route <目标>` 看匹配到哪条 | 汇总路由覆盖了不属于自己的网段，形成黑洞 |

**掩码不一致故障详解**（高频）：

```
主机 A: 192.168.1.10 / 255.255.255.0   （认为 192.168.1.0~255 都是本地）
网关  : 192.168.1.1  / 255.255.255.128 （认为只有 192.168.1.0~127 是本地）
```
A ping 网关是通的（都在 0~127 内）。但 A ping `192.168.1.200`：
- A 认为同网段 → 直接 ARP，收不到回应 → 不通
- 而 200 实际在网关看来属于另一个子网

**症状表现为"部分地址通、部分不通"**，非常迷惑人。排查方法：**逐台核对掩码**。

---

## ⑥ 考点提示 + 自测题

### 考点

- 子网划分本身在 CCNP 里不单独出题，但**几乎每道涉及地址的题都要求你会算**。
- **通配符掩码**在 ACL、OSPF network 语句、route-map 中必考。
- **路由汇总与过度汇总的后果**是 ENARSI 排障重点。
- `169.254.x.x` = DHCP 失败，是送分题。

### 自测题

**1.** `172.16.30.0/22` 的网络地址是什么？

<details><summary>答案</summary>
**172.16.28.0**。/22 掩码 255.255.252.0，第三字节块大小 = 256−252 = 4，边界为 0,4,8,...,28,32。30 落在 28~31 区间，所以网络地址是 172.16.28.0，广播地址 172.16.31.255，可用 172.16.28.1 ~ 172.16.31.254（1022 个）。
</details>

**2.** 要写一条 ACL 只匹配 `10.1.4.0/22` 这个网段，通配符掩码应该是多少？

<details><summary>答案</summary>
`0.0.3.255`

因为 /22 = 255.255.252.0，取反：255−255=0, 255−255=0, 255−252=3, 255−0=255。

完整语句：`access-list 10 permit 10.1.4.0 0.0.3.255`
</details>

**3.** 一条点对点串行链路需要几个 IP？用什么掩码最省？

<details><summary>答案</summary>

需要 2 个 IP（两端各一个）。

- **/30**（255.255.255.252）：4 个地址，去掉网络和广播，剩 2 个可用。最传统、兼容性最好的做法。
- **/31**（255.255.255.254）：RFC 3021 规定点对点链路上不需要网络/广播地址，2 个地址都可用。**更省一半**，现代设备都支持，Cisco 需要在接口下配 `ip address x.x.x.x 255.255.255.254`。

大规模网络（几百条互联链路）用 /31 能省下可观的地址空间。但注意：**部分老设备和某些网管系统不支持 /31**，规划前先确认。
</details>

**4.** 网络里有 `10.1.1.0/24` 和 `10.1.2.0/24` 两个网段在 R1 后面，`10.1.3.0/24` 在 R2 后面。R1 向核心通告了汇总路由 `10.1.0.0/22`。会发生什么？

<details><summary>答案</summary>

**`10.1.3.0/24` 的流量会被错误吸引到 R1，形成黑洞。**

`10.1.0.0/22` 覆盖 10.1.0.0 ~ 10.1.3.255，包含了本不属于 R1 的 `10.1.3.0/24`。

核心路由器的路由表里会同时有：
- `10.1.0.0/22` → R1（来自 R1 的汇总）
- `10.1.3.0/24` → R2（来自 R2 的明细）

按**最长匹配原则**，去 10.1.3.x 的流量还是会走 R2 —— 所以**只要 R2 的明细路由存在，暂时不会出问题**。

**但是**，一旦 R2 那条链路故障、明细路由消失，流量就会 fallback 到 R1 的 `/22`，而 R1 根本没有去 10.1.3.0 的路由，包被丢弃 → **黑洞**。

**这是过度汇总的典型危害：平时看不出来，故障时雪上加霜。**

**正确做法**：R1 只汇总自己实际拥有的部分 —— `10.1.1.0/24` 和 `10.1.2.0/24` 不连续对齐（1 和 2 无法合成一条 /23，因为 /23 边界是偶数：0-1、2-3），所以应该分别通告两条明细，或者重新规划地址让它们可汇总。

**这也说明了地址规划的重要性**：如果当初把 R1 后面规划成 10.1.0.0 和 10.1.1.0，就能干净地汇总成 10.1.0.0/23。
</details>

**5.** 主机配置 `192.168.1.63/26`，能正常上网吗？

<details><summary>答案</summary>

**不能**。/26 块大小 64，`192.168.1.0/26` 的范围是 0~63，其中 **63 是广播地址**，不能分配给主机。

多数操作系统和网络设备会直接拒绝这个配置（Cisco 会报 `Bad mask ... for address`）。少数系统允许配上但网络行为异常。

正确的可用范围是 `192.168.1.1 ~ 192.168.1.62`。
</details>
