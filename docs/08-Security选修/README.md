## 为什么 Enterprise 工程师需要懂安全

```
   ★ 现实：企业网络里，"网络"和"安全"的边界越来越模糊 ★
   
   · 接入层的 802.1X 是网络配置还是安全配置？
   · 出口的 ACL 是路由策略还是防火墙规则？
   · SD-Access 的 SGT 是网络分段还是访问控制？
   · 零信任要求"网络本身就是策略执行点"
   
   ★ 答案：都是。安全已经内建在网络里了 ★
```

**ENCOR 的安全域占 20%**，而 CCNP Enterprise 持证者在实际工作中，**至少一半时间在处理和安全相关的需求**。

## ★ 一个核心认知

```
   ★ 传统安全模型："城堡与护城河" ★
      · 边界防火墙隔离内外
      · 内网默认可信
      · 一旦突破边界，横向移动畅通无阻
   
        ↓ 为什么失效
   
   · 云和 SaaS 让"边界"消失
   · 远程办公让"内网"无处不在
   · 内部威胁和供应链攻击绕过边界
   · 勒索软件的横向传播证明"内网可信"是错的
   
        ↓
   
   ★★ 零信任："从不信任，永远验证" ★★
      · 不基于位置授权，基于身份授权
      · 微分段：内网之间也要策略控制
      · 持续验证，而不是一次认证永久放行
```

**这个转变正在发生，而网络工程师是它的主要实施者。**
