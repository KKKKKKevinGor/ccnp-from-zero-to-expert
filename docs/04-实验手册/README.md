## 实验环境选择

| 方案 | 成本 | 二层支持 | 推荐度 | 说明 |
|:--|:--|:--|:--|:--|
| **Cisco CML 2.x** | 官方付费 | ✅ 完整 | ★★★★★ | 官方镜像，行为最接近真机，考试模拟度最高 |
| **EVE-NG Community** | 免费 | ✅ 完整（需 IOL/vIOS-L2） | ★★★★★ | **本手册以此为基准** |
| **PNETLab** | 免费 | ✅ | ★★★★ | EVE-NG 分支，自带实验商店 |
| **GNS3** | 免费 | ⚠️ 需配 IOU/IOL | ★★★ | 老牌方案，二层特性支持较弱 |
| **Packet Tracer** | 免费 | ⚠️ 有限 | ★ | **只够 CCNA，不要用它学 CCNP** |

**Packet Tracer 的缺陷**（为什么不推荐）：
- BGP 支持极其残缺（没有 route-map、community、聚合）
- MPLS 完全不支持
- 组播支持有限
- VRF 不支持
- 很多 `show` 命令的输出是简化的假数据

**搭建步骤见 [00-实验环境搭建](00-实验环境搭建.md)。**

## 实验方法论（★ 决定实验价值的关键）

**很多人做实验的方式是错的**：抄配置 → 能通了 → 下一个。这样做完 10 个实验，什么也没学到。

**正确的方法**：

```
   ① 先看拓扑和需求，★ 自己想配置方案 ★
      不要看答案。想不出来再看。
        ↓
   ② 敲配置（手敲，不复制粘贴）
      敲错了正好，排查的过程就是学习
        ↓
   ③ 验证功能
      用 show 命令逐项确认，不只是 "ping 通了"
        ↓
   ④ ★★★ 故障注入 ★★★
      每个实验最后都有"故障注入"环节
      ★ 这是整个实验中最有价值的部分 ★
        ↓
   ⑤ 观察症状 → 独立推导根因 → 验证
      不要直接看答案
        ↓
   ⑥ 修复，再次验证
        ↓
   ⑦ 写实验笔记
      · 我遇到了什么问题
      · 我怎么定位的
      · 根因是什么
      · 下次怎么更快定位
```

**★ 第 ④ 步是关键。** ENARSI 的考试和真实工作，考的都是"看到症状能不能想到根因"。**只有亲手制造过那个症状，你才认得出来。**

## 实验通用规范

**每个实验开始前**：
```cisco
! 保存一个干净的起点，方便重做
R1# copy running-config flash:lab-start.cfg

! 关闭域名解析（避免敲错命令卡 30 秒）
R1(config)# no ip domain-lookup

! Console 不被日志打断
R1(config)# line console 0
R1(config-line)# logging synchronous
R1(config-line)# exec-timeout 0 0

! 不分页
R1# terminal length 0
```

**每个实验结束后**：
```cisco
! 恢复到起点
R1# configure replace flash:lab-start.cfg
! 或
R1# write erase
R1# reload
```

**地址规划约定**（本手册统一）：

| 用途 | 网段 |
|:--|:--|
| Loopback（Router ID） | `X.X.X.X/32`（X = 设备编号） |
| 设备互联 P2P | `10.0.<小编号><大编号>.0/30` |
| 用户网段 | `192.168.<VLAN>.0/24` |
| 服务器网段 | `10.1.30.0/24` |
| 管理网段 | `10.1.99.0/24` |

**例**：R1 和 R2 之间 = `10.0.12.0/30`，R1 用 `.1`，R2 用 `.2`。
