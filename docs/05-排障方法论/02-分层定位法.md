# 02 · 分层定位法

> **核心思想：每一层都有【一个明确的验证手段】。逐层排除，不猜。**

## ① 总览

```
   ┌─────────────────────────────────────────────────────────┐
   │ L7 应用层    │ 抓包看协议交互、应用日志                    │
   ├─────────────────────────────────────────────────────────┤
   │ L4 传输层    │ ★ telnet <ip> <port> ★                    │
   ├─────────────────────────────────────────────────────────┤
   │ L3 网络层    │ ★ ping / traceroute / show ip route ★     │
   ├─────────────────────────────────────────────────────────┤
   │ L2 链路层    │ ★ show mac address-table / trunk / stp ★  │
   ├─────────────────────────────────────────────────────────┤
   │ L1 物理层    │ ★ show interfaces status / counters ★     │
   └─────────────────────────────────────────────────────────┘
```

**排查方向**：
- **完全不通** → 自底向上（L1 → L7）
- **ping 通但业务不通** → 从 L4 开始
- **完全没头绪** → 从 L3 二分

## ② L1 物理层

### 核心命令

```cisco
! ── 一眼扫全部接口 ──
SW1# ★ show interfaces status ★
Port      Name          Status         Vlan    Duplex  Speed Type
Gi1/0/1   PC-01         ★connected★    10      a-full  a-1000 10/100/1000BaseTX
Gi1/0/2                 ★notconnect★   10        auto    auto 10/100/1000BaseTX
Gi1/0/3   Printer       ★err-disabled★ 10        auto    auto 10/100/1000BaseTX
Gi1/0/4   AP-01         ★disabled★     900       auto    auto 10/100/1000BaseTX
Gi1/0/5                 ★inactive★     30        auto    auto 10/100/1000BaseTX
```

### ★ 状态判读表

| Status | Vlan 列 | 含义 | 排查方向 |
|:--|:--|:--|:--|
| **connected** | 数字 | ✅ 正常 | — |
| **notconnect** | 数字 | 物理未连接 | 网线、对端接口、光模块 |
| **err-disabled** | `err-disabled` | 被保护机制关闭 | `show int status err-disabled` 看原因 |
| **disabled** | 数字 | 被 `shutdown` | `no shutdown` |
| **★ inactive ★** | 数字 | **VLAN 不存在** | 创建该 VLAN |
| monitoring | — | SPAN 目的口 | 正常 |
| **faulty** | — | 硬件故障 | 换端口/换板卡 |

> **★ `inactive` 最容易被忽略**：端口配了 `switchport access vlan 30`，但 VLAN 30 从来没创建过。端口物理上通，逻辑上不工作。

### 错误计数器

```cisco
SW1# ★ show interfaces GigabitEthernet1/0/1 ★
  ...
  5 minute input rate 1000 bits/sec, 2 packets/sec
     12345 packets input, 1234567 bytes
     Received 100 broadcasts (50 multicasts)
     ★ 0 runts, 0 giants ★, 0 throttles
     ★ 15 input errors, 15 CRC ★, 0 frame, 0 overrun, 0 ignored
     ...
     0 output errors, 234 collisions, 0 interface resets
     ★ 45 late collision ★, 0 deferred
     ★ Total output drops: 12345 ★
```

| 计数器 | 含义 | ★ 指向 |
|:--|:--|:--|
| **`CRC` / `FCS-Err`** | 校验失败 | ★ **物理层**：线缆劣质/超长、接头氧化、电磁干扰、光衰 |
| `Align-Err` | 帧对齐错误 | 物理层，常伴随 CRC |
| `runts` | < 64 字节 | 冲突、双工不匹配 |
| `giants` | > MTU | MTU 不匹配、未预期的 VLAN 标签 |
| **`late collision`** | 64 字节后的冲突 | ★★ **双工不匹配**（几乎可直接定性） |
| `collisions` | 正常冲突 | 半双工环境；全双工下应为 0 |
| **`output drops`** | 输出丢弃 | ★ **拥塞**（缓冲区满） |
| `input errors` | 输入错误总和 | 看细分项 |
| `interface resets` | 接口复位 | 链路不稳定、时钟问题（串口） |
| `throttles` | 输入队列满 | CPU 处理不过来 |

### ★ 三个高价值的判断

**① `late collision` > 0 → 双工不匹配**
```cisco
SW1# show interfaces Gi1/0/1 | include late
     ★ 45 late collision ★, 0 deferred

SW1# show interfaces Gi1/0/1 | include duplex|Duplex
  ★ Half-duplex ★, 100Mb/s
     ↑ 一端半双工

! 对端
SW2# show interfaces Gi1/0/1 | include duplex
  ★ Full-duplex ★, 100Mb/s
     ↑ 另一端全双工 → ★ 找到了 ★
```
**修复**：两端都 auto，或两端都手工写死。**绝不能一端 auto 一端手工**。

**② `CRC` 持续增长 → 物理层质量问题**
```cisco
! 光模块诊断
SW1# ★ show interfaces GigabitEthernet1/0/49 transceiver detail ★
                             Optical   Optical
        Temperature  Voltage  Tx Power  Rx Power
Port    (Celsius)    (Volts)   (dBm)     (dBm)
Gi1/0/49    42.5      3.31      -2.5    ★ -28.5 ★
                                          ↑↑↑↑↑
                     ★ 接收光功率过低！正常应在 -3 ~ -15 dBm ★
```
**修复**：清洁光纤接头、换跳线、换光模块、检查光衰。

**③ `output drops` 增长 → 拥塞**
```cisco
SW1# show interfaces Gi1/0/24 | include drops|rate
  5 minute output rate ★ 980000000 ★ bits/sec        ← 接近千兆满载
  Total output drops: ★ 45678 ★
```
**修复**：升级带宽、配 QoS、找出占带宽的流量（NetFlow）。

### err-disable 排查

```cisco
SW1# ★ show interfaces status err-disabled ★
Port      Name    Status              ★ Reason ★
Gi1/0/3   Printer err-disabled        ★ psecure-violation ★
Gi1/0/10          err-disabled        ★ bpduguard ★
Gi1/0/15          err-disabled        ★ udld ★

SW1# show errdisable recovery
ErrDisable Reason            Timer Status
-----------------            --------------
bpduguard                    ★ Enabled ★
psecure-violation            Disabled
udld                         Disabled
Timer interval: 300 seconds
```

**常见的 err-disable 原因**：

| 原因 | 触发条件 | 修复 |
|:--|:--|:--|
| `bpduguard` | PortFast 口收到 BPDU（私接交换机） | 拔掉私接设备 |
| `psecure-violation` | Port Security 超过 MAC 上限 | 调整 maximum 或清理 |
| `udld` | 检测到单向链路 | 换光纤/光模块 |
| `link-flap` | 接口频繁 up/down | 查物理层 |
| `dhcp-rate-limit` | DHCP 报文超速 | 调整 limit rate |
| `arp-inspection` | ARP 检测失败 | 查 DAI 配置和静态绑定 |
| `storm-control` | 风暴超阈值 | 查环路或异常流量 |

**恢复**：
```cisco
! 手工
SW1(config-if)# shutdown
SW1(config-if)# no shutdown

! ★ 自动恢复（推荐）
SW1(config)# errdisable recovery cause bpduguard
SW1(config)# errdisable recovery cause psecure-violation
SW1(config)# errdisable recovery interval 300
```

## ③ L2 链路层

### 核心命令

```cisco
! ── MAC 地址表 ──
SW1# show mac address-table
SW1# ★ show mac address-table address 0050.5600.aabb ★
SW1# show mac address-table interface Gi1/0/1
SW1# show mac address-table count

! ── Trunk（★ 四段输出法）──
SW1# ★ show interfaces trunk ★

! ── STP ──
SW1# show spanning-tree summary
SW1# show spanning-tree vlan 10
SW1# ★ show spanning-tree vlan 10 detail | include occurr|from ★
SW1# show spanning-tree inconsistentports
SW1# show spanning-tree blockedports

! ── EtherChannel ──
SW1# ★ show etherchannel summary ★
SW1# show lacp neighbor

! ── VLAN ──
SW1# show vlan brief
SW1# show interfaces Gi1/0/1 switchport
```

### ★ `show interfaces trunk` 四段输出法

```cisco
SW1# show interfaces trunk

! ── 第 1 段：模式、封装、状态、Native VLAN ──
Port        Mode  Encapsulation  Status    ★ Native vlan ★
Gi1/0/24    on    802.1q         trunking     999
                                              ↑ ★ 对比两端！不一致会"焊接"两个 VLAN

! ── 第 2 段：配置上允许哪些 VLAN ──
Port        ★ Vlans allowed on trunk ★
Gi1/0/24    10,20,30

! ── 第 3 段：允许的 VLAN 里，哪些实际存在于 VLAN 数据库 ──
Port        Vlans allowed and active in management domain
Gi1/0/24    10,20,30

! ── 第 4 段：★ 最终真正转发的 ★（还要过 STP 这一关）──
Port        Vlans in spanning tree forwarding state and not pruned
Gi1/0/24    10,20
```

**★ 排障技巧：从第 4 段往上看**

```
   第 4 段没有 VLAN 30？
        ↓ 往上看
   第 3 段有吗？
        ├─ 没有 → 往上看第 2 段
        │         ├─ 没有 → ★ 配置里就没放行 ★
        │         └─ 有   → ★ VLAN 没创建 ★
        └─ 有   → ★ 被 STP 阻塞了 ★
```

**这个方法能在 30 秒内定位 90% 的 Trunk 问题。**

### ★ 环路的三个证据

```cisco
! ① CPU 异常（STP 进程占用高）
SW1# show processes cpu sorted | exclude 0.00
CPU utilization for five seconds: ★ 95% ★/78%
 PID Runtime(ms) Invoked uSecs 5Sec 1Min 5Min TTY Process
  85   12345678  9876543  1250 ★45.2%★ ... ★ Spanning Tree ★

! ② 流量暴涨
SW1# show interfaces | include rate|is up
GigabitEthernet1/0/10 is up, line protocol is up
  5 minute input rate ★ 890000000 ★ bits/sec
  5 minute output rate ★ 890000000 ★ bits/sec

! ③ ★★ MAC 表震荡（最确定的证据）★★
SW1# show mac address-table address 0050.5600.aabb
  10    0050.5600.aabb    DYNAMIC     ★ Gi1/0/1 ★
! 立刻再执行一次
SW1# show mac address-table address 0050.5600.aabb
  10    0050.5600.aabb    DYNAMIC     ★ Gi1/0/10 ★
!                                       ↑ ★ 同一 MAC 在两个口跳变 = 环路 ★
```

**★ 找震荡源头**：
```cisco
SW1# ★ show spanning-tree vlan 10 detail | include occurr|from ★
  Number of topology changes ★ 12453 ★ last change occurred 00:00:03 ago
          ★ from GigabitEthernet1/0/10 ★
                                    ↑ ★ 直接告诉你是哪个端口 ★
```

### `show etherchannel summary` 标志速查

```cisco
SW1# show etherchannel summary
Group  Port-channel  Protocol    Ports
1      ★ Po1(SU) ★    LACP       Gi1/0/23★(P)★  Gi1/0/24★(I)★
```

| 标志 | 含义 | 正常？ |
|:--|:--|:--|
| **`(P)`** | bundled（已捆绑） | ✅ |
| **`(I)`** | stand-alone | ❌ **参数不一致** |
| **`(s)`** | suspended | ❌ **LACP 协商失败** |
| `(D)` | down | ❌ 物理层 |
| `(H)` | Hot-standby | 热备 |
| **`(SU)`** | Layer2 + in use | ✅ |
| **`(RU)`** | Layer3 + in use | ✅ |
| `(SD)` | Layer2 + down | ❌ |
| `(SM)` | min-links 未满足 | ⚠️ |

**排障**：
- `(I)` → `show logging | include EC-5`（日志明确说哪个参数不一致）
- `(s)` → `show lacp neighbor`（空 = 对端没发 LACPDU）

## ④ L3 网络层

### 核心命令

```cisco
! ── 接口 ──
R1# show ip interface brief
R1# show ip interface <接口>

! ── 路由 ──
R1# ★ show ip route <目标IP> ★              ! ★ 看某个 IP 匹配哪条路由
R1# show ip route <网段> <掩码>              ! 精确查某条路由
R1# show ip route summary
R1# show ip cef <目标IP>                     ! 硬件转发表

! ── 连通性（★ 永远指定 source）──
R1# ★ ping <目标> source <源接口> ★
R1# ★ ping <目标> size 1500 df-bit ★         ! ★ MTU 测试
R1# traceroute <目标> source <源接口>

! ── ARP ──
R1# show ip arp [vrf NAME]
R1# clear arp-cache

! ── HSRP ──
R1# ★ show standby brief ★
R1# show track [brief]

! ── VRF（★ 别忘了加 vrf）──
R1# show ip route ★ vrf NAME ★
R1# ping ★ vrf NAME ★ <目标>
```

### ★ 三个必须养成的习惯

**① `ping` 永远加 `source`**

```cisco
! ✗ 不加 source
R1# ping 10.2.1.1
! → 路由器用【出接口 IP】作为源
! → 如果对端没有回到那个网段的路由，会显示"不通"
! → ★ 但用户的实际流量是通的 ★

! ✅ 加 source
R1# ★ ping 10.2.1.1 source Vlan10 ★
! → 模拟真实的业务源地址
```

**★ 这个习惯能省掉大量"测出来不通但用户说能用"的困惑。**

**② 单向不通先查回程**

```cisco
! A 能 ping B，B 不能 ping A
! ★ 80% 是回程路由缺失 ★

! 在 A 上（去程）
R-A# show ip route 192.168.20.0
D    192.168.20.0/24 [90/3072] via ...        ✓ 有

! ★ 在 B 上（回程）★
R-B# show ip route 192.168.10.0
★ % Network not in table ★                    ← ★ 找到了 ★
```

**③ 大包测试是常规动作**

```cisco
R1# ping <目标> size 100
!!!!!                                          ✓
R1# ★ ping <目标> size 1500 df-bit ★
★ M.M.M ★                                      ← ★ MTU 问题 ★
```

**只要路径上有任何隧道（GRE/IPsec/VXLAN/MPLS），就要测这个。**

### `show ip route <目标IP>` 的价值

```cisco
R1# ★ show ip route 10.1.1.5 ★
Routing entry for ★ 10.1.1.0/24 ★
  Known via "★ ospf 1 ★", distance ★ 110 ★, metric 200, ★ type extern 2 ★
  ★ Tag 200 ★
  Last update from 10.0.12.2 on GigabitEthernet0/1, 00:05:12 ago
  Routing Descriptor Blocks:
  ★ * 10.0.12.2 ★, from 2.2.2.2, 00:05:12 ago, via GigabitEthernet0/1
      Route metric is 200, traffic share count is 1
```

**这一条命令告诉你**：
- 匹配到哪条路由（**最长匹配**的结果）
- 来源协议和 AD
- **路由类型**（intra area / extern 2 → 判断是不是回流路由）
- **Tag**（重分发的痕迹）
- 下一跳和出接口
- 最后更新时间

### traceroute 的读法

```cisco
R1# traceroute 10.2.1.1 source Loopback0
  1 10.0.12.2  4 msec  4 msec  4 msec        ← 正常
  2 10.0.23.3  8 msec  8 msec  8 msec        ← 正常
  3 ★ * * * ★                                 ← ★ 从这一跳开始不通 ★
  4 * * *
```

| 输出 | 含义 |
|:--|:--|
| 正常 IP + 时间 | 这一跳可达 |
| **`* * *`** | 该跳不响应（可能是防火墙拦了 ICMP，也可能是真的不通） |
| **IP 往复出现** | ★ **路由环路** |
| `!H` | Host unreachable |
| `!N` | Network unreachable |
| `!A` | ★ **被 ACL 禁止**（Administratively prohibited） |
| **`M`**（ping 的输出） | ★ **需要分片但 DF 置位 = MTU 问题** |

> **`* * *` 不一定是故障**：很多设备默认不回 ICMP Time Exceeded（安全加固），或 MPLS 网络关闭了 TTL 传播。**要结合"后续跳是否正常"判断**。

## ⑤ L4 传输层

### ★ 核心工具：`telnet <ip> <port>`

**这是分层定位最有价值的一个命令。**

```cisco
R1# telnet 10.1.30.50 8080
```

| 结果 | 含义 | 下一步 |
|:--|:--|:--|
| **`Open`** | ✅ **端口通** | 问题在**应用层** |
| **`Connection refused`** | 收到 **RST** → **服务端没监听** | 找应用团队（服务没起/崩了） |
| **超时（十几秒）** | ★ **被中间设备静默丢弃** | 查 **ACL / 防火墙 / 安全组** |

**★ 这个二分判断五秒钟就能决定该找谁。**

### 抓包验证

```cisco
! Cisco 内嵌抓包
R1# monitor capture CAP interface Gi0/0 both
R1# monitor capture CAP match ipv4 any any
R1# monitor capture CAP start
! ... 复现问题 ...
R1# monitor capture CAP stop
R1# show monitor capture CAP buffer brief
```

**★ 三种典型的抓包结果**：

```
   ① 服务未启动：
      客户端 → SYN
      服务器 → ★ RST, ACK ★                    ← 明确拒绝
   
   ② 被静默丢弃：
      客户端 → SYN
      客户端 → SYN  (重传)
      客户端 → SYN  (重传)
      ★ 没有任何回应 ★                          ← 中间设备 drop
   
   ③ ★ 服务器慢（不是网络慢）★：
      客户端 → SYN                    T=0
      服务器 → SYN+ACK                T=★15ms★  ← 网络往返正常
      客户端 → ACK                    T=15ms
      客户端 → HTTP GET               T=16ms
      服务器 → HTTP 200 OK            T=★8500ms★ ← ★ 服务器处理了 8.5 秒 ★
      
      ★★ 结论：网络没问题，服务器慢 ★★
```

**★ 第 ③ 种是网络工程师最有价值的能力**：用数据证明问题不在网络，而不是靠嘴争论。

## ⑥ 服务层排查

### DHCP

```cisco
! 现象：拿到 169.254.x.x
! ★ 排查顺序（覆盖 90% 的情况）★

! ① 端口 VLAN 对吗
SW1# show interfaces Gi1/0/5 switchport | include Access Mode
SW1# show interfaces Gi1/0/5 status              ← 看是不是 inactive

! ② PortFast 配了吗
SW1# show spanning-tree interface Gi1/0/5 portfast

! ③ ★ helper-address ★
SW1# ★ show ip interface Vlan10 | include Helper ★

! ④ DHCP Snooping 的 trust
SW1# ★ show ip dhcp snooping ★
SW1# show ip dhcp snooping binding

! ⑤ 服务器侧
DHCP# show ip dhcp pool
DHCP# show ip dhcp binding
DHCP# show ip dhcp conflict
DHCP# ★ show ip route <giaddr> ★                 ← ★ 回程路由

! ⑥ 日志
SW1# show logging | include DHCP
```

### DNS

```cisco
! 现象：ping IP 通、ping 域名不通
! 或：所有访问慢 5 秒

! ★ 分别测 A 和 AAAA ★
$ dig A www.example.com          # 快
$ dig AAAA www.example.com       # ★ 超时？→ AAAA 查询问题 ★

! ★ 测 TCP 53 ★
$ dig +tcp www.example.com       # 大响应需要 TCP

! ★ 主站能开但页面白屏 → 比 TTL 量级 ★
$ dig @<内网DNS> cdn.example.com +noall +answer   # 上万秒？
$ dig @223.5.5.5 cdn.example.com +noall +answer   # 权威只给几十秒
                                 # ★ 差几百倍 → min-TTL 覆盖 ★

! 设备侧
R1# show hosts
R1# show run | include ip name-server|ip domain
```

> **★ 服务层最容易被漏掉的一层 ★**
>
> `ping` 通、`traceroute` 通、`telnet` 端口通——三层四层全绿，用户还是说"打不开"。
> 这时问题往往在**解析**而不是**转发**：解析给了一个通不到的地址，链路本身是好的。
>
> **判断口诀**：**换个 DNS 试试**。换公共 DNS 就好 = 解析问题，与链路无关。

### NTP

```cisco
R1# ★ show ntp status ★
★ Clock is synchronized ★, stratum 4, reference is 10.1.30.61
   ↑ ★ 必须是 synchronized ★

R1# ★ show ntp associations ★
  address        ref clock      st  when poll reach delay offset disp
★*★~10.1.30.61   203.107.6.88   3    45   64  ★377★ 1.234 0.567 0.123
 ↑                                             ↑
★ * = 当前同步源 ★              ★ 377（八进制）= 最近8次全成功 ★
```

| reach 值 | 含义 |
|:--|:--|
| **377** | ✅ 最近 8 次全成功 |
| 0 | ❌ 一次都没成功 |
| 1 | 只有最近一次成功（刚开始） |

**★ `stratum 16` + `.INIT.` + `reach 0` = 完全联系不上**。

### NAT

```cisco
R1# ★ show ip nat statistics ★
Total active translations: 47 (1 static, 46 dynamic; 46 extended)
★ Outside interfaces: ★
  GigabitEthernet0/1                        ← ★ 必须有
★ Inside interfaces: ★
  GigabitEthernet0/0                        ← ★ 必须有
Hits: 128456  Misses: 0

R1# show ip nat translations | include <某IP>
R1# ★ show ip nat translations | include <某IP> | count ★    ← 查是谁占用最多
```

**★ NAT 不工作的头号原因：忘了标记 `ip nat inside/outside`**。

## ⑦ ★ 症状 → 层 → 命令 速查表

**打印出来贴工位。**

| 症状 | 层 | ★ 第一个命令 |
|:--|:--|:--|
| 接口 down/down | L1 | `show interfaces status` |
| 接口 up/down | L2 | `show interfaces` 看封装/keepalive |
| 端口 `inactive` | L2 | `show vlan brief`（VLAN 不存在） |
| 端口 err-disabled | L1/L2 | `show int status err-disabled` |
| 通但极慢，late collision | L1 | 查双工 |
| CRC 增长 | L1 | `show int transceiver detail` |
| output drops 增长 | L1 | 拥塞，查流量 |
| 同 VLAN 不通 | L2 | `show mac address-table` |
| **同 VLAN 跨交换机不通** | L2 | ★ `show interfaces trunk` |
| 两个 VLAN 意外互通 | L2 | Native VLAN 不一致 |
| CPU 高 + MAC 震荡 | L2 | ★ 环路 |
| **跨 VLAN 全不通，SVI 正常** | L3 | ★ `show run \| inc ^ip routing` |
| 跨网段不通 | L3 | `show ip route <目标>` |
| **A→B 通，B→A 不通** | L3 | ★ 在 B 上查回程路由 |
| **小包通大包不通** | L3 | ★ `ping size 1500 df-bit` |
| traceroute IP 往复 | L3 | ★ 路由环路，查重分发 |
| 主备不切换 | L3 | `show standby brief`（P 列）+ `show track` |
| **ping 通业务不通** | L4 | ★ `telnet <ip> <port>` |
| 立即 refused | L4 | 服务未启动 |
| 超时无响应 | L4 | ACL/防火墙 drop |
| **拿到 169.254.x.x** | 服务 | ★ `show ip int Vlan10 \| inc Helper` |
| **证书"尚未生效"** | 服务 | ★ `show ntp status` |
| **固定延迟 5 秒** | 服务 | ★ `dig AAAA <域名>` |
| **主站能开、页面白屏** | 服务 | ★ 内网/公共 DNS **比 TTL 量级** |
| **时好时坏、找不到规律** | 服务 | ★ 看 TTL 是否在倒数（缓存周期） |
| ping 域名不通 | 服务 | DNS |
| 内网通外网不通 | 服务 | ★ `show ip nat statistics` |

## ⑧ 一个完整的分层排查演练

**故障**："PC1 打不开公司的 ERP 系统"

```cisco
! ═══ L1 物理层 ═══
SW3# show interfaces GigabitEthernet1/0/1 status
Gi1/0/1   PC-01   ★ connected ★   10   a-full  a-1000
                                   ↑ 状态和 VLAN 都正常 ✓

SW3# show interfaces Gi1/0/1 | include error|drop
     0 input errors, 0 CRC
     Total output drops: 0
                                   ✓ L1 通过

! ═══ L2 链路层 ═══
SW3# show mac address-table interface Gi1/0/1
  10    0050.5600.aabb    DYNAMIC     Gi1/0/1
                                   ✓ MAC 学到了

SW3# show interfaces trunk
Port      Vlans in spanning tree forwarding state and not pruned
Gi1/0/23  ★ 10,20 ★
                                   ✓ VLAN 10 在转发 ✓ L2 通过

! ═══ L3 网络层 ═══
PC1> ping 192.168.10.1              ← 网关
Reply from 192.168.10.1             ✓

PC1> ping 10.1.30.50                ← ERP 服务器
Reply from 10.1.30.50: time=8ms     ✓ L3 通过

! ★ 别忘了 MTU 测试 ★
SW1# ping 10.1.30.50 size 1500 df-bit source Vlan10
!!!!!                               ✓ MTU 正常

! ═══ L4 传输层 ═══
PC1> ★ telnet 10.1.30.50 8080 ★
Connecting To 10.1.30.50...
★ Could not open connection: 连接超时 ★
                                   ✗ ★ 找到问题层了 ★

! ★ 超时（不是 refused）= 被静默丢弃 = 中间有 ACL/防火墙 ★

! 对比测试
PC1> telnet 10.1.30.50 80
（连上了）                          ← 80 通，8080 不通

! ═══ 定位具体位置 ═══
! 逐跳测
SW1# telnet 10.1.30.50 8080         ← 从网关测
（连上了）                          ✓ SW1 到服务器通

! ★ 所以问题在 PC1 到 SW1 之间，或者是基于源地址的策略 ★

SW1# show access-lists
Extended IP access list VLAN10-POLICY
    10 permit tcp 192.168.10.0 0.0.0.255 host 10.1.30.50 eq www (245 matches)
    20 ★ deny ip any any log (1245 matches) ★
                                ↑ ★ 大量被拒绝 ★

SW1# show logging | include IPACCESSLOG
%SEC-6-IPACCESSLOGP: list VLAN10-POLICY denied tcp 192.168.10.10(51234) 
-> 10.1.30.50(★ 8080 ★), 24 packets
                            ↑ ★ 根因确认 ★

! ═══ 修复 ═══
SW1(config)# ip access-list extended VLAN10-POLICY
SW1(config-ext-nacl)# ★ 15 permit tcp 192.168.10.0 0.0.0.255 host 10.1.30.50 eq 8080 ★

! ═══ 验证 ═══
SW1# show access-lists VLAN10-POLICY
    10 permit tcp ... eq www (245 matches)
    ★ 15 permit tcp ... eq 8080 (45 matches) ★    ← 有命中 ✓
    20 deny ip any any log (1245 matches)

PC1> telnet 10.1.30.50 8080
★ Open ★                                          ✓
```

**★ 整个过程的关键**：
1. **逐层排除**，每层都有明确的验证命令
2. **`telnet <ip> <port>` 定位到 L4**
3. **"超时 vs refused" 的区分**指向 ACL 而非服务
4. **`show access-lists` 的命中计数 + 日志**给出精确根因
5. **修复后用命中计数验证**
